# Metis 디자인 적용 지시서

이 문서 하나가 작업 지시 전부다. 처음부터 끝까지 읽고, 아래 순서대로 멈추지 말고 끝까지 진행하라.

## 목표

이 저장소는 이미 동작하는 Metis 데스크탑 앱이다(React, TypeScript, Tailwind CSS, Radix UI, Vite, Electron).
해야 할 일은 두 가지다.

1. **기능과 화면 구성은 그대로 두고 모습을** `docs/design/DESIGN.md`와 시안대로 바꾼다.
2. **앞으로 추가되는 화면과 컴포넌트도 같은 규칙을 따르도록 장치를 넣는다**(토큰, 공용 컴포넌트, `AGENTS.md`, 자동 검사).

새로 만드는 작업이 아니다. 기존 컴포넌트와 스타일을 고쳐서 적용한다.

## 기준 자료

| 파일 | 내용 |
|---|---|
| `docs/design/DESIGN.md` | **단일 기준.** 원칙, 토큰, 상태 규칙, 컴포넌트, 새 컴포넌트·새 화면 규칙, 화면 명세, 구현 지침 |
| `docs/design/metis-final-prototype.html` | 모습과 동작의 시안. 브라우저로 열어 모든 화면을 확인한다. 뒤쪽은 이미지 데이터와 시안 도구 스크립트이니 `<style>` 블록과 화면 마크업만 읽는다 |
| `docs/design/metis-tokens.css` | 토큰 원본(CSS 변수). 라이트, 다크, Aura |
| `docs/design/AGENTS.design.md` | 루트 `AGENTS.md`에 넣을 규칙 |
| `docs/design/assets/` | 로고 이미지 |
| `scripts/design-check.mjs` | 디자인 규칙 자동 검사 |

DESIGN.md와 시안이 다르면 DESIGN.md를 따르고, 차이를 최종 보고에 적는다.

## 기본 결정 (바꾸려면 이 구역만 고친다)

- 스택과 구조: 저장소의 기존 폴더 구조, 스타일 방식, Radix 불러오는 방식을 그대로 따른다. 없는 도구를 새로 넣지 않는다.
- 테마: 기존 선택지 4개(라이트, 다크, Aura, 시스템)를 유지한다. 값은 DESIGN.md 3.1.
- 토큰: 저장소에 이미 테마 변수 체계가 있으면 그 변수의 값을 바꾸고, 없는 것만 추가한다. 새 체계를 병행해서 만들지 않는다.
- 회사 로고: 저장소에 이미 있는 HCT 2.0 로고를 쓴다. `assets/hct20-preview.png`는 저해상도라 쓰지 않는다.
- Metis 로고: 저장소에 원본이 있으면 원본을, 없으면 `assets/metis-logo.png`를 쓴다.
- 현재 앱에 없던 요소(DESIGN.md 13.2의 6번)는 아래처럼 한다.
  - 툴팁, 입력창 단축키 안내, 사이드바 단축키 힌트: 넣는다. 단축키는 설정에 저장된 값을 읽어 표시한다.
  - 답변 아래 "복사": 넣는다.
  - 답변 아래 "같은 요청 다시 실행": 저장소에 같은 기능이 이미 있을 때만 연결한다. 없으면 넣지 않고 최종 보고에 적는다.
- 범위: DESIGN.md 8장의 모든 화면.

## 규칙

1. **기능을 바꾸지 않는다.** 라우팅, 상태 관리, 백엔드 호출, 설정 키와 저장 형식, 단축키 동작은 그대로 둔다.
2. **항목을 빼거나 더하지 않는다.** 예외는 DESIGN.md 8장에 "변경"으로 적힌 것뿐이다.
3. **기존 컴포넌트를 고쳐 쓴다.** 같은 역할의 컴포넌트를 새로 만들어 병행하지 않는다.
4. **색과 크기는 토큰만 쓴다.** 컴포넌트에 값을 직접 쓰지 않는다.
5. 시안의 `x-dc`, `sc-for`, `sc-if` 태그, 파일 끝의 스크립트, 클래스 이름(`.btn` 등)을 베끼지 않는다.
6. 시안의 예시 데이터를 앱에 넣지 않는다. DESIGN.md 13.1의 항목은 구현하지 않는다.
7. 문구를 바꿀 때는 기존 번역 파일의 키를 고친다. 한국어 외 언어도 깨지지 않게 한다.
8. 시안에 없는 기존 화면이나 요소는 지우지 말고 DESIGN.md 6장과 7장의 규칙으로 맞춘다.
9. 원격 저장소에 올리거나 배포하지 않는다. 의존성은 꼭 필요할 때만 추가하고 최종 보고에 적는다.

## 작업 순서

1. **파악**
   - 저장소 구조, UI 소스 폴더, 공용 UI 컴포넌트 폴더, 테마 구현 위치를 읽는다.
   - `package.json`에서 Tailwind, Radix, Electron의 버전을 확인한다(DESIGN.md 11.2, 11.4의 방식 선택).
   - 시안의 화면과 저장소의 컴포넌트 파일을 짝지은 표를 만든다.
2. **장치 넣기**
   - `docs/design/AGENTS.design.md`의 내용을 루트 `AGENTS.md`에 넣는다(있으면 덧붙이고 없으면 만든다). `<UI 소스 폴더>`를 실제 경로로 바꾼다.
   - `node scripts/design-check.mjs <UI 소스 폴더> --baseline=scripts/design-baseline.json --update-baseline`으로 현재 상태를 기준선으로 기록한다.
   - `package.json`의 `scripts`에 `"design:check": "node scripts/design-check.mjs <UI 소스 폴더> --baseline=scripts/design-baseline.json"`을 넣는다.
3. **토큰과 테마**
   - 기존 테마 변수를 DESIGN.md 3장 값으로 바꾸고 없는 토큰을 추가한다(라이트, 다크, Aura).
   - Tailwind에 연결한다(DESIGN.md 11.2).
   - 대응표를 `docs/design/TOKEN_MAP.md`에 적는다(디자인 토큰 ↔ 저장소 변수 ↔ Tailwind 클래스).
   - 글꼴을 앱에 함께 넣는다(DESIGN.md 11.4).
4. **공용 컴포넌트**: 버튼, 아이콘 버튼, 입력, 토글, 구간 선택, 드롭다운, 메뉴와 팝오버, 선택 카드, 체크 상자, 태그, 탭, 카드와 행, 창, 토스트, 툴팁을 DESIGN.md 4장과 5장대로 고친다. 화면 파일에 흩어진 같은 모양의 코드는 공용 컴포넌트로 바꾼다.
5. **셸**: 타이틀바와 사이드바(8.2, 8.3).
6. **화면**: 홈과 입력창(8.4, 8.5) → 채팅 화면과 사이드 패널(8.6, 8.7) → 레시피(8.8) → 스킬(8.9) → 스케줄러(8.10) → 채팅 기록(8.11).
7. **설정**: 분류 7개와 제공업체 설정 창(8.12).
8. **검수**
   - `--update-baseline`으로 기준선을 다시 기록해 위반 수가 줄었는지 확인하고, 남은 위반을 최종 보고에 적는다.
   - 아래 완료 기준을 직접 확인하고 어긋난 곳을 고친다.

## 멈추고 물어야 하는 경우

아래 경우에만 멈춘다. 그 밖의 판단은 스스로 내리고 최종 보고에 적는다.

- 기능이나 저장 형식을 바꾸지 않고는 시안대로 만들 수 없을 때
- 기존 파일을 지워야 할 때
- 계정이나 비밀 값이 필요할 때
- 이 문서의 규칙끼리 충돌해서 어느 쪽도 지킬 수 없을 때

## 완료 기준

- DESIGN.md 8장의 모든 화면이 시안과 같은 모습이다. 시안과 나란히 열어 비교한다.
- 라이트, 다크, Aura에서 모든 화면이 정상으로 보이고, 글자 대비가 4.5:1 이상이다.
- 누를 수 있는 모든 요소에 올림·누름·포커스 상태가 있고, 메뉴 항목이 마우스와 키보드로 선택된다.
- 기존 기능이 모두 그대로 동작한다: 채팅 전송, 모델·프로젝트·익스텐션 선택, 레시피, 스케줄러, 채팅 기록, 설정 저장.
- 루트 `AGENTS.md`에 UI 디자인 규칙이 들어 있고, `docs/design/TOKEN_MAP.md`가 있다.
- `npm run design:check`가 통과하고, 기준선의 위반 수가 작업 전보다 줄었다.
- 기존 테스트, 린트, 타입 검사, 빌드가 통과한다.

## 최종 보고

1. 화면과 컴포넌트 파일을 짝지은 표
2. 바꾼 파일 목록과 화면별 확인 결과
3. 고친 공용 컴포넌트 목록과, 새로 만든 것이 있으면 그 이유
4. 실행한 검사와 결과(디자인 검사의 작업 전후 위반 수 포함). 돌리지 못한 검사는 그렇다고 적는다.
5. 시안이나 DESIGN.md와 다르게 만든 곳과 이유
6. 스스로 내린 판단 목록
7. DESIGN.md 13.2의 확인 사항에 대해 저장소에서 알아낸 것(Aura 테마의 기존 값, 채팅 화면의 기존 구성, Tailwind와 Electron 버전 등)
8. 남은 문제
