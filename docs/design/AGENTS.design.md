## UI 작업 규칙 (Metis 디자인 시스템)

화면이나 컴포넌트를 만들거나 고치는 작업은 **`docs/design/DESIGN.md`를 따릅니다.** 작업 전에 읽습니다.

- 새 컴포넌트: 6장을 먼저 읽습니다. 5장에 같은 역할이 있으면 새로 만들지 않습니다.
- 새 화면: 7장의 틀 중 하나로 만듭니다.
- 기존 화면 수정: 8장의 그 화면 항목과 4장(상태)을 읽습니다.

**무엇이 기준인가**
- 규칙은 `DESIGN.md`, 토큰 값은 `docs/design/metis-tokens.css`입니다.
- `docs/design/metis-final-prototype.html`은 보기용 그림입니다. 문서와 다르면 문서를 따르고 차이를 보고합니다. 시안의 CSS에서 값을 읽어 옮기지 않습니다.
- 저장소의 실제 이름은 `docs/design/TOKEN_MAP.md`(토큰 ↔ 저장소 변수 ↔ Tailwind 클래스)를 따릅니다.

**항상 지키는 것**
1. 색·글자 크기·모서리·간격·층은 토큰으로만 씁니다. 값을 직접 쓰지 않습니다. 없는 값이 필요하면 토큰을 먼저 추가합니다(6.6).
2. 강조색은 켜진 토글·체크·라디오, 포커스 링, 진행 표시, 링크 글자에만 씁니다.
3. 누를 수 있는 것은 `button`이나 Radix 부품으로 만들고, 기본·올림·누름·포커스·쓸 수 없음 상태를 모두 줍니다.
4. 값을 넣거나 고르는 컨트롤에는 바탕과 3:1 이상으로 구분되는 경계를 둡니다. 글자는 4.5:1 이상입니다.
5. 메뉴·팝오버·창·툴팁은 Radix의 Portal을 쓰고, 닫히면 포커스를 연 버튼으로 돌려줍니다.
6. 되돌릴 수 없는 동작은 확인 창을 거칩니다. 입력 오류는 그 칸 아래에 적습니다(토스트 금지).
7. 그라데이션, 반투명 유리 효과, 꾸미는 움직임, 운영체제 기본 `<select>`·`alert`·`confirm`을 쓰지 않습니다.

**바꾸지 않는 것**: 기능, 데이터·설정의 저장 방식과 저장 시점, 백엔드 통신, Aura 테마의 색 값, 번역 구조, 의존성. 바꿔야 할 것 같으면 멈추고 묻습니다.

**끝내기 전에**
```bash
node scripts/design-check.mjs <UI 소스 폴더> --tokens <토큰 파일> --baseline scripts/design-baseline.json
```
- 통과해야 합니다. 기준선을 올려서 통과시키지 않습니다.
- 이 검사는 상태·대비·키보드를 보지 못합니다. `DESIGN.md` 12.2의 항목을 직접 확인하고, 확인하지 못한 항목은 보고에 적습니다.
- 새 컴포넌트를 만들었으면 `DESIGN.md` 5장에 6.4 양식으로 등록하고 14장에 한 줄 적습니다.

**멈추고 묻는 경우**: `DESIGN.md`의 원칙(2장)을 바꿔야 할 때, 문서의 두 규칙이 서로 맞지 않을 때, 기존 화면의 요소를 문서로 설명할 수 없을 때.
