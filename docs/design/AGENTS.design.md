# UI 디자인 규칙 (Metis)

> 이 내용을 저장소 루트의 `AGENTS.md`에 넣는다. `AGENTS.md`가 이미 있으면 이 구역을 덧붙이고, 없으면 이 내용으로 새로 만든다.

화면(UI)에 닿는 작업을 할 때는 아래를 따른다. 화면과 무관한 작업에는 적용하지 않는다.

## 시작하기 전에

1. `docs/design/DESIGN.md`를 읽는다. 이 문서가 화면의 단일 기준이다.
   - 기존 화면을 고칠 때: 3, 4, 5, 8장
   - **새 컴포넌트를 만들 때: 6장부터**
   - **새 화면을 만들 때: 7장부터**
2. `docs/design/TOKEN_MAP.md`가 있으면 읽는다. 디자인 토큰과 이 저장소의 변수·Tailwind 클래스의 대응표다.
3. 모습이 궁금하면 `docs/design/metis-final-prototype.html`을 브라우저로 연다. 시안은 예시이고 규칙은 DESIGN.md다.

## 지킬 것

- **색·크기·모서리·간격은 토큰으로만 쓴다.** 색상 값(`#fff`, `rgb()`), Tailwind 기본 색(`bg-blue-500`), 임의 색(`bg-[#123456]`)을 쓰지 않는다.
- **공용 컴포넌트를 쓴다.** 버튼, 입력, 토글, 메뉴 등은 공용 UI 폴더의 것을 가져다 쓴다. 화면 파일 안에서 같은 모양을 다시 짜지 않는다.
- **새 컴포넌트는 DESIGN.md 6장의 순서를 거친다**: 기존 것 재사용 → 종류 추가 → 조합 → Radix 부품 → 그래도 없을 때만 신규. 만들었으면 6.4 양식으로 DESIGN.md 5장에 등록하고 14장에 한 줄 적는다.
- **새 화면은 DESIGN.md 7장의 틀 중 하나로 만든다.**
- 누를 수 있는 모든 요소에 기본·올림·누름·포커스·쓸 수 없음 상태를 넣는다(4장).
- Radix 부품의 상태는 `data-state`, `data-highlighted`, `data-disabled`로 스타일을 잡는다. 메뉴·팝오버·창·툴팁은 Portal을 쓴다.
- 그라데이션, 발광, 반투명 유리 효과(`backdrop-blur`), 가는 글자(300 이하)를 쓰지 않는다.
- 운영체제 기본 셀렉트(`<select>`), `alert()`, `confirm()`을 쓰지 않는다.
- 누를 수 있는 것은 `button`이거나 Radix 부품이다. 아이콘만 있으면 `aria-label`과 툴팁을 붙인다.
- 문구는 DESIGN.md 9장을 따르고 번역 파일에 넣는다.
- 규칙에 없는 값이 필요하면 컴포넌트에 직접 쓰지 말고, 토큰을 먼저 추가한다(6.6).

## 끝내기 전에

1. `node scripts/design-check.mjs <UI 소스 폴더> --baseline=scripts/design-baseline.json`을 돌린다. 오류가 0이어야 한다. (기준선 파일이 없으면 `--baseline` 없이 돌린다.)
2. 기존 린트, 타입 검사, 테스트, 빌드를 돌린다.
3. 라이트·다크·Aura에서 화면을 확인하고, 마우스 올림·누름·Tab 이동을 확인한다.
4. 보고에 적는다: 바꾼 파일, 새로 만들거나 고친 컴포넌트, 추가한 토큰, 돌린 검사와 결과, DESIGN.md와 다르게 한 곳과 이유.

## 멈추고 물어야 하는 경우

- DESIGN.md 2장의 원칙을 바꿔야만 할 수 있는 일일 때
- 기능이나 저장 형식을 바꾸지 않고는 요구한 화면을 만들 수 없을 때
- 기존 파일을 지워야 할 때
