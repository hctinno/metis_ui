# Metis 디자인 시스템 (DESIGN.md)

Metis 데스크탑 앱의 화면을 만들고 고칠 때 따르는 **단일 기준 문서**입니다.
지금 있는 화면뿐 아니라 **앞으로 추가될 화면과 컴포넌트**도 이 문서의 규칙으로 만듭니다.

- 기준일: 2026-11-19
- 기준 시안: `metis-final-prototype.html` (브라우저에서 바로 열림)
- 토큰 원본: `metis-tokens.css`
- 로고: `assets/`
- 자동 검사: `scripts/design-check.mjs` (12장)
- 앱 구성: React, TypeScript, Tailwind CSS, Radix UI, Vite, Electron (Windows 배포)

## 0. 이 문서를 읽는 순서

| 하려는 일 | 읽을 곳 |
|---|---|
| 기존 화면을 이 디자인으로 바꾸기 | 3 → 4 → 5 → 8 → 11 |
| **새 컴포넌트 만들기** | **6** → 3 → 4 → 5 |
| **새 화면 만들기** | **7** → 6 → 5 |
| 문구 쓰기 | 9 |
| 끝났는지 확인하기 | 12 |

규칙이 서로 부딪치면 이 순서로 따릅니다: **원칙(2장) → 토큰(3장) → 상태 규칙(4장) → 컴포넌트(5장) → 화면 명세(8장) → 시안**.
시안은 예시이고 이 문서가 규칙입니다. 시안과 이 문서의 값이 다르면 작업을 멈추지 말고, 이 문서를 따른 뒤 차이를 보고에 적습니다.

## 1. 범위

**바꾸는 것**
- 색, 글자, 간격, 모서리, 컨트롤의 모습과 상태 표현
- 타이틀바와 사이드바의 배치
- 8장에 "변경"으로 적은 화면별 정리 항목

**바꾸지 않는 것**
- 화면 종류와 메뉴 구성, 설정 항목의 종류와 의미
- 기능, 동작, 데이터와 설정의 저장 방식, 백엔드와의 통신
- 테마 선택지 4개(라이트, 다크, Aura, 시스템)

**시안을 읽을 때 주의**
- 시안 파일 끝의 런타임 스크립트와 `<x-dc>`, `<sc-for>`, `<sc-if>` 태그는 시안 도구용입니다. 구조를 가져다 쓰지 않습니다.
- 시안의 클래스 이름(`.btn`, `.inp` 등)은 이 문서에서 컴포넌트를 가리키는 이름으로만 씁니다. 앱에서는 기존 컴포넌트와 Tailwind 클래스로 구현합니다.
- 시안의 채팅 목록, 레시피, 일정, 모델 목록, 프로젝트 경로는 예시 데이터입니다.
- 시안은 글꼴을 인터넷에서 불러옵니다. 앱은 글꼴을 함께 넣어 배포합니다(11.4).

## 2. 원칙

컨셉은 **모노 톤의 평면 화면**이고, 입력과 컨트롤의 세부는 **Apple Human Interface Guidelines(HIG)** 방식입니다.

1. **모노 톤.** 화면은 무채색입니다. 주요 버튼도 먹색(라이트)이나 흰색(다크)입니다.
2. **강조색은 네 곳에만.** 켜진 토글·체크, 포커스 링, 진행 표시, 링크. 그 밖에는 쓰지 않습니다.
3. **평면.** 그라데이션, 발광, 반투명 유리 효과를 쓰지 않습니다. 그림자는 떠 있는 것(메뉴, 창, 입력창, 툴팁)에만 씁니다.
4. **면으로 구분.** 사이드바·타이틀바는 `--side`, 본문은 `--bg`. 떠 있는 테두리 패널로 화면을 나누지 않습니다.
5. **컨트롤은 채움으로.** 버튼·입력·태그는 테두리 대신 옅은 채움(`--fill`)을 씁니다. 올리면 한 단계, 누르면 두 단계 진해집니다.
6. **한 화면에 주요 버튼 하나.** 나머지는 기본, 고스트, 위험 버튼으로 낮춥니다.
7. **모든 누를 수 있는 것은 상태를 가집니다.** 기본, 올림, 누름, 포커스가 반드시 있습니다(4장).
8. **상태는 색과 모양을 함께.** 색만으로 구분하지 않습니다.
9. **움직임은 상태를 알릴 때만.** 꾸미는 움직임은 넣지 않습니다. "움직임 줄이기" 설정에서는 모두 끕니다.
10. **여러 동작은 메뉴 하나로.** 항목마다 아이콘을 늘어놓지 않고 ⋯ 메뉴에 모읍니다.

## 3. 토큰

색·크기·모서리·간격은 **토큰으로만** 씁니다. 컴포넌트에 값을 직접 쓰지 않습니다.
원본은 `metis-tokens.css`이고, Tailwind에 연결하는 방법은 11.2에 있습니다.

### 3.1 색

루트 요소의 `data-theme`(`light` | `dark` | `aura`)으로 정해집니다. 테마 설정이 "시스템"이면 `prefers-color-scheme`에 따라 `light` 또는 `dark`를 넣습니다.
**앱에 이미 테마 변수 체계가 있으면 새 체계를 따로 만들지 않습니다.** 기존 변수의 값을 아래에 맞춰 바꾸고, 대응 관계를 `docs/design/TOKEN_MAP.md`에 적습니다(11.2).

| 토큰 | 용도 | 라이트 | 다크 | Aura (임시) |
|---|---|---|---|---|
| `--bg` | 본문 바탕 | `#F5F5F6` | `#0F0F10` | `#F6F5F2` |
| `--side` | 사이드바, 타이틀바 | `#FFFFFF` | `#19191B` | 라이트와 같음 |

| `--line` | 구분선, 카드 테두리 | `#E8E8EA` | `#29292C` | `#E8E5DF` |

그 밖의 토큰(diff 색 `--add-bg`, `--add-tx`, `--del-bg`, `--del-tx`, 개수 배지 바탕 `--segbg`, 그림자 `--pop`, `--shadow`)과 크기·모서리·움직임·층의 이름 붙은 값은 `metis-tokens.css`에 있습니다.

- 본문과 보조 글자는 바탕 대비 4.5:1 이상입니다. 값을 바꿀 때 이 기준을 유지합니다.
- 강조색 글자는 `--accent`가 아니라 `--atext`를 씁니다.
- `--fill` 계열과 `--hover`는 반투명 값입니다. 어떤 면 위에 올려도 같은 단계로 보이게 하려는 것입니다.
- **Aura는 임시 정의입니다.** 현재 앱의 Aura 테마 모습을 확인하지 못했습니다(13.2).
- OS의 고대비 설정(`prefers-contrast: more`)에서는 `--line`을 진하게, `--mute`를 `--text2`로, `--ring`을 `--accent`로 바꿉니다.

**어떤 색을 고를지**

| 쓰려는 곳 | 토큰 |
|---|---|
| 화면 바탕 | `--bg` (사이드바·타이틀바는 `--side`) |
| 카드, 창, 메뉴, 입력창 | `--panel` |
| 컨트롤 면(버튼, 입력, 태그, 구간 선택) | `--fill` → 올림 `--fill2` → 누름 `--fill3` |
| 묶음 안의 옅은 면(선택 카드) | `--group` |
| 선택된 행 | `--sel` |
| 목록 행 올림 | `--hover` |
| 구분선, 카드 테두리 | `--line` |
| 글자 | `--text` → 보조 `--text2` → 설명 `--mute` |
| 켜짐, 선택 표시, 진행 | `--accent` (글자는 `--atext`, 옅은 면은 `--soft`) |
| 성공 / 주의 / 위험 | `--ok` / `--warn` / `--danger` (위험의 옅은 면은 `--dsoft`) |

### 3.2 글꼴

| 용도 | 글꼴 스택 |
|---|---|
| 화면 | `-apple-system, BlinkMacSystemFont, 'SF Pro Text', Inter, 'Apple SD Gothic Neo', 'Noto Sans KR', 'Malgun Gothic', sans-serif` |
| 워드마크 "Metis" | `'Sora', -apple-system, BlinkMacSystemFont, Inter, sans-serif`, 굵기 600, 자간 -0.03em |
| 코드, 경로, 모델 이름 | `'JetBrains Mono', ui-monospace, Menlo, Consolas, monospace`, 합자 끔 |

Windows에서는 Inter와 Noto Sans KR이 쓰입니다.

### 3.3 글자 크기

단계는 7개뿐입니다. 이 밖의 크기는 쓰지 않습니다. 굵기는 400, 500, 600, 700만 씁니다(300 이하는 쓰지 않습니다).

| 이름 | 크기 / 줄 높이 | 굵기 | 쓰는 곳 |
|---|---|---|---|
| 큰 제목 | 26 / 32px | 700 | 페이지 제목, 설정 분류 제목 |
| 제목 | 22 / 26px | 700 | 예비(큰 제목 아래 단계가 필요할 때) |
| 작은 제목 | 17 / 22px | 600 | 예비 |
| 구역 제목 | 15 / 20px | 600 | 창 제목, 빈 상태 제목, 채팅 제목 |
| 본문 | 13px / 1.5 | 400 | 대화, 행 이름, 버튼(500, 주요 버튼 600) |
| 작은 글자 | 12px | 400~600 | 작은 버튼, 구간 선택, 탭, 코드 |
| 보조 | 11px | 400 / 600 | 설명, 시간, 그룹 이름(600), 툴팁, 단축키 |

- 본문 자간 -0.006em. 숫자가 바뀌는 곳(시간, 개수)은 `font-variant-numeric: tabular-nums`.
- 한글은 단어 중간에서 줄이 바뀌지 않게 합니다(`word-break: keep-all; overflow-wrap: break-word`).
- 홈 화면의 시각만 예외로 46.8px(3.6em), 굵기 400입니다. 인사말은 18.2px(1.4em).

## 4. 상태 규칙

**누를 수 있는 모든 요소**에 아래 상태가 있어야 합니다. 새 컴포넌트도 이 표에서 값을 가져옵니다.

| 상태 | 채움형(버튼, 입력, 태그) | 목록 행(사이드바, 메뉴, 카드 행) | 주요 버튼 |
|---|---|---|---|
| 기본 | `--fill` | 면 없음 | `--btn` 면, `--btn-ink` 글자 |
| 올림 | `--fill2` | `--hover` (메뉴 항목은 `--fill2`) | 불투명도 88% |
| 누름 | `--fill3`, 98% 크기 | 98% 크기 | 98% 크기 |
| 키보드 포커스 | 3.5px `--ring` 외곽선, 간격 1px | 같음 | 같음 |
| 선택됨, 켜짐 | `--accent` 면(토글·체크) 또는 `--soft` 면과 `--atext` 글자 | `--sel` 면, 굵기 500 | - |
| 열림(메뉴가 붙은 버튼) | `--soft` 면과 `--atext` 글자, 화살표 180도 | `--hover` 면 유지 | - |
| 쓸 수 없음 | 불투명도 42%, 누름 반응 없음, `aria-disabled` | 같음 | 같음 |
| 처리 중 | 글자 앞에 회전 고리, 다시 누를 수 없음 | - | 같음 |

- 입력 칸의 포커스는 외곽선 대신 `--panel` 면과 3.5px `--ring` 그림자입니다.
- 위험 동작은 `--dsoft` 면과 `--danger` 글자입니다. 올리면 면이 진해집니다. 위험 버튼을 주요 버튼으로 만들지 않습니다.
- 올림은 마우스가 있을 때만(`@media (hover: hover)`) 적용합니다.
- Radix 컴포넌트에서는 상태를 `data-state`, `data-highlighted`, `data-disabled` 속성으로 잡습니다(11.3).

## 5. 컴포넌트

괄호 안은 시안의 클래스 이름입니다. "Radix"는 구현에 쓸 기본 부품입니다. 저장소에 같은 역할의 컴포넌트가 이미 있으면 그것을 고쳐 씁니다.

### 5.1 버튼 (`.btn`)

| 종류 | 모습 | 쓰는 곳 |
|---|---|---|
| 기본 | `--fill` 면, 글자 500 | 취소, 가져오기, 새로고침, 편집, 변경 |
| 주요 (`.pri`) | `--btn` 면, `--btn-ink` 글자, 600 | 새 채팅, 레시피 생성, 저장, 허용, 전송 |
| 위험 (`.danger`) | `--dsoft` 면, `--danger` 글자 | 삭제, 초기화 |
| 고스트 (`.ghost`) | 면 없음, `--text2` 글자. 올리면 `--fill` | 거부, 선택 해제, 옵션 표시 |
| 옅은 강조 (`.tint`) | `--soft` 면, `--atext` 글자 | 예비 |

- 높이 28px, 모서리 999px, 좌우 12px. 작은 버튼(`.sm`)은 24px, 12px 글자.
- 아이콘은 글자 앞에 16px, 사이 6px.
- 다른 화면이나 창을 여는 버튼은 이름 끝에 말줄임표를 붙입니다(9장).
- 아이콘만 있는 버튼(`.ibtn`)은 30px 원형이고, `aria-label`과 툴팁이 있어야 합니다.

### 5.2 입력 (`.inp`)

- 높이 28px, 모서리 8px, 테두리 없음, `--fill` 면. 올리면 `--fill2`.
- 포커스: `--panel` 면, 3.5px `--ring`.
- 검색 칸과 메뉴 안의 검색 칸은 모서리 999px, 좌우 14px.
- 여러 줄 입력은 모서리 10px, 최소 높이 76px.
- 숫자 입력은 폭 112px, 오른쪽 정렬, 뒤에 단위를 보조 글자로.
- 모든 입력에 보이는 라벨이나 `aria-label`. 라벨은 12px 600, 포커스가 들어가면 `--atext`.
- 값이 바뀌면 바로 저장합니다. 저장 버튼을 따로 두지 않습니다(13.2 확인 필요).

### 5.3 선택 컨트롤

| 컨트롤 | 쓰는 때 | 모습 | Radix |
|---|---|---|---|
| 토글 (`.tgl`) | 켜고 끄기 | 38x22, 꺼짐 `--fill3`, 켜짐 `--accent` | Switch |
| 구간 선택 (`.seg`) | 선택지 2~4개 | 캡슐, 선택 칸은 `--segsel` 면과 옅은 그림자 | ToggleGroup(single) |
| 드롭다운 (`.dd`) | 선택지 5개 이상 | 28px 캡슐, 오른쪽 화살표 | Select 또는 DropdownMenu |
| 선택 카드 (`.opt`) | 설명이 필요한 선택 | `--group` 면, 선택되면 `--soft` | RadioGroup |
| 체크 상자 (`.cbx`) | 여러 개 고르기 | 16px, 켜짐 `--accent` | Checkbox |

- 운영체제 기본 셀렉트(`<select>`)를 쓰지 않습니다.
- 켜고 끄는 설정에 체크 상자를 쓰지 않습니다. 토글을 씁니다.

### 5.4 메뉴와 팝오버 (`.menu`)

- `--panel` 면, 모서리 13px, 안쪽 5px, 그림자 `--pop`. 최소 폭 200px.
- 항목: 최소 높이 28px, 모서리 8px, 좌우 10px. 올림(키보드 이동 포함) `--fill2`.
- 선택된 항목은 왼쪽 체크 표시로 알립니다. 면을 칠하지 않습니다.
- 위험 항목은 `--danger` 글자, 올리면 `--dsoft` 면. 목록 맨 아래에 둡니다.
- 한 번에 하나만 열리고, 바깥을 누르거나 항목을 고르면 닫힙니다. 토글이 든 팝오버는 눌러도 열려 있습니다.
- 채팅 입력창의 팝오버는 위로, 그 밖의 메뉴는 아래로 열립니다.
- 메뉴가 열려 있는 동안 그 버튼은 "열림" 상태로 보입니다.
- Radix: DropdownMenu, Popover. 항목 강조는 `:hover`가 아니라 `data-highlighted`로 잡습니다.

### 5.5 카드와 행 (`.card`, `.row`)

- 카드: `--panel` 면, `--line` 1px 테두리, 모서리 12px, 그림자 없음.
- 행 묶음: 카드 안에 행을 쌓고 행 사이에 `--line` 1px. 행은 최소 44px, 안쪽 8px 14px.
- 행: 왼쪽에 이름(13px)과 설명(11px `--mute`), 오른쪽에 컨트롤 하나.
- 행에 마우스를 올리면 아주 옅은 면(글자색 3%)이 깔립니다.
- 격자 카드(채팅 기록, 익스텐션): 최소 폭 260px. 올리면 테두리가 진해집니다.
- 카드나 행을 통째로 움직이는 효과(이동, 기울임)는 넣지 않습니다(11.5).

### 5.6 사이드바 항목

- 내비게이션 항목(`.nav`): 높이 30px, 모서리 8px, 아이콘 16px(`--text2`)과 이름. 현재 화면은 `--sel` 면, 굵기 500.
- 구역 제목(`.sec`): 11px 600 `--mute`, 접힘 화살표, 오른쪽에 + 버튼. + 버튼은 평소 흐리고 구역에 마우스를 올리면 선명해집니다.
- 채팅 행(`.srow`): 한 줄. 제목(넘치면 말줄임)과 시간. 실행 중이나 승인 대기일 때만 앞에 상태 점.
- 프로젝트 행: 폴더 아이콘, 이름, 채팅 수. 누르면 아래에 채팅이 들여쓰기로 나옵니다.
- Radix: Collapsible(접이식 구역).

### 5.7 태그 (`.tag`)

높이 24px 캡슐, `--fill` 면. 누를 수 있는 태그는 올리면 `--fill2`. 채팅 입력창의 모델·프로젝트·익스텐션 태그는 28px.

### 5.8 탭 (`.tab`)

12px, 높이 42px. 선택된 탭은 `--text` 글자 600과 아래 2px 선. Radix: Tabs.

### 5.9 창(모달)과 토스트

- 창: 가운데, 폭 최대 540px, 모서리 20px, 뒤는 `--scrim`. 제목 줄(15px 600, 오른쪽 닫기), 본문, 버튼 줄.
- 버튼 줄: 오른쪽 정렬. 취소가 왼쪽, 주요 동작이 오른쪽. 위험 동작은 맨 왼쪽에 떨어뜨립니다.
- 토스트: 아래 가운데 캡슐, `--text` 면과 `--bg` 글자, 2.6초 뒤 사라짐, `role="status"`.
- Radix: Dialog, AlertDialog(확인 창), Toast.

### 5.10 툴팁

- 아이콘만 있는 버튼에는 반드시 붙입니다. 글자가 있는 버튼에는 붙이지 않습니다.
- 11px, 모서리 5px, `--tip` 면과 `--tip-ink` 글자, 0.9초 뒤 표시. 키보드 포커스에서는 바로 표시.
- 단축키가 있으면 이름 뒤에 함께 적습니다(예: 탐색 메뉴 Ctrl+/). 단축키는 사용자가 바꿀 수 있으므로 **설정에 저장된 값을 읽어** 표시합니다.
- Radix: Tooltip(`delayDuration` 900).

### 5.11 상태 점 (8px)

| 상태 | 색 | 모양 |
|---|---|---|
| 실행 중 | `--accent` | 원, 깜빡임 |
| 승인 대기 | `--warn` | 둥근 사각 |
| 완료, 켜짐 | `--ok` | 원 |
| 꺼짐 | 테두리만 | 빈 원 |
| 오류 | `--danger` | 둥근 사각 |

상태 점에는 상태 이름을 `aria-label`로 붙입니다.

### 5.12 채팅 입력창 (`.composer`)

- `--panel` 면, 테두리 없음, 모서리 22px, 0.5px 실선과 그림자. 포커스가 들어가면 3.5px `--ring`.
- 내용만큼 높이가 늘어납니다(최소 2줄, 최대 약 9줄, 그 뒤는 스크롤).
- 비어 있으면 전송 버튼이 흐립니다(쓸 수 없음 상태).
- 실행 중에는 전송 버튼이 중지 버튼으로 바뀝니다.
- 포커스가 들어가면 아래에 단축키 안내가 나타납니다(Enter 전송, Shift+Enter 줄바꿈, / 스킬 부르기).
- 아래 줄: 모델 태그, 프로젝트 태그, (여백), 익스텐션 태그, 첨부, 전송.

### 5.13 대화 요소

- 사용자 말풍선: 오른쪽 정렬, 최대 폭 86%, `--bubble` 면.
- 답변: 테두리 없는 본문, 최대 68자 폭.
- 할 일 카드: 제목 줄에 진행 수(1/3). 완료는 초록 원에 체크, 진행 중은 회전 고리, 예정은 빈 원.
- 도구 호출 카드: 행마다 펼침 화살표, 익스텐션 이름, 호출 내용(코드 글꼴), 결과. 누르면 출력이 펼쳐지고 화살표가 90도 돕니다.
- 승인 카드: `--warn` 테두리. 호출 내용, 이유, 버튼 3개(허용, 항상 허용, 거부).
- 답변 아래 동작: 복사, 같은 요청 다시 실행. 평소 흐리고 올리면 선명해집니다(13.2 확인 필요).
- 응답 작성 중: 점 3개.

### 5.14 그 밖의 세부

- 스크롤바는 평소 숨기고, 그 영역에 마우스를 올렸을 때만 보입니다.
- 글자 선택 색은 `--accent` 30%. 입력 커서 색은 `--accent`.
- 타이틀바, 사이드바, 버튼의 글자는 끌어서 선택되지 않게 합니다. 본문과 대화는 선택됩니다.
- 단축키 힌트: "새 채팅"과 "설정" 항목은 올렸을 때만 오른쪽에 단축키가 보입니다.
- 빈 상태: 카드 안에 옅은 사각형, 제목(15px 600), 설명 한 줄.

## 6. 새 컴포넌트를 만드는 규칙

### 6.1 만들기 전에 (이 순서로 확인)

1. **5장에 같은 역할이 있는가.** 있으면 그것을 씁니다. 모습이 조금 달라야 해도 새로 만들지 않습니다.
2. **기존 컴포넌트에 종류를 하나 더하면 되는가.** 되면 종류(variant)를 추가합니다.
3. **기존 컴포넌트를 조합하면 되는가.** 되면 조합합니다(예: 카드 + 행 + 토글).
4. **Radix에 그 동작을 하는 부품이 있는가.** 있으면 그 위에 스타일을 입힙니다. 키보드 조작과 포커스 처리를 직접 만들지 않습니다.
5. 위 넷이 모두 아닐 때만 새로 만듭니다.

### 6.2 새 컴포넌트가 지켜야 하는 것

- [ ] 색은 3.1의 토큰만 씁니다. 색상 값을 직접 쓰지 않습니다.
- [ ] 글자 크기는 3.3, 높이는 3.4, 모서리는 3.5, 간격은 3.6에서 고릅니다.
- [ ] 누를 수 있으면 4장의 상태(기본, 올림, 누름, 포커스, 쓸 수 없음)를 모두 가집니다.
- [ ] 라이트, 다크, Aura에서 모두 확인합니다.
- [ ] 누를 수 있는 것은 `button`이거나 Radix 부품입니다. `div`에 클릭을 달지 않습니다.
- [ ] 아이콘만 있으면 `aria-label`과 툴팁이 있습니다.
- [ ] 키보드만으로 쓸 수 있습니다(Tab으로 이동, Enter나 Space로 실행, Esc로 닫기).
- [ ] 색만으로 상태를 구분하지 않습니다. 모양이나 글자가 함께 바뀝니다.
- [ ] 움직임이 있으면 3.8의 값을 쓰고, "움직임 줄이기"에서 꺼집니다.
- [ ] 문구는 9장을 따르고 번역 파일에 넣습니다.
- [ ] 그라데이션, 발광, 반투명 유리 효과, 가는 글자를 쓰지 않습니다.
- [ ] `node scripts/design-check.mjs`가 통과합니다.
- [ ] 6.4 양식으로 이 문서 5장에 등록합니다.

### 6.3 값 고르는 법

| 정할 것 | 고르는 법 |
|---|---|
| 높이 | 한 줄 컨트롤은 28px. 목록 속의 작은 것은 24px. 목록 행은 30px(사이드바)이나 44px(설정) |
| 모서리 | 누르는 컨트롤은 999px. 글자를 입력하는 칸은 8px. 담는 상자는 12px. 떠 있는 것은 13px(메뉴)이나 20px(창) |
| 면 | 컨트롤은 `--fill`. 담는 상자는 `--panel`과 `--line` 테두리. 상자 안의 선택지는 `--group` |
| 글자 | 이름은 13px, 설명은 11px `--mute`, 제목은 15px 600 |
| 강조 | 켜짐·선택·진행에만 `--accent`. 그 밖에는 무채색 |
| 그림자 | 다른 것 위에 뜨면 `--pop`. 화면을 가리는 창이면 `--shadow`. 그 밖에는 없음 |
| 아이콘 | 16px, 선 굵기 1.6, `currentColor`. 저장소의 기존 아이콘 묶음을 씁니다 |

### 6.4 등록 양식

새 컴포넌트를 만들면 5장 끝에 아래 양식으로 추가하고, 14장 변경 기록에 한 줄 적습니다.

```md
### 5.x 이름 (컴포넌트 파일 경로)

- 쓰는 때: (한 문장. 기존 컴포넌트로 안 되는 이유 포함)
- 구조: (부품과 순서)
- 치수: 높이, 모서리, 안쪽 여백 (3장의 값으로)
- 색: 기본 / 올림 / 누름 / 선택 / 쓸 수 없음 (토큰 이름으로)
- 키보드: (조작 방법)
- Radix: (쓴 부품, 없으면 "없음")
- 쓰지 않는 때: (헷갈리기 쉬운 경우)
```

### 6.5 예시: 규칙대로 만든 두 가지

아래 둘은 지금 앱에 없는 컴포넌트입니다. 규칙을 적용하면 어떻게 정해지는지 보여 주는 예입니다.

**진행 막대**
- 쓰는 때: 얼마나 끝났는지 숫자로 알 수 있는 작업(내려받기, 여러 파일 처리). 끝을 모르면 회전 고리를 씁니다.
- 구조: 바탕 막대 + 채워진 막대, 오른쪽에 보조 글자로 "3/10".
- 치수: 높이 6px, 모서리 999px(누르는 것은 아니지만 가는 막대는 끝을 둥글게).
- 색: 바탕 `--fill2`, 채움 `--accent`(진행은 강조색을 쓰는 네 곳 중 하나). 완료되면 `--ok`.
- 접근성: `role="progressbar"`, `aria-valuenow`, `aria-valuemax`. 색과 함께 숫자를 보여 줍니다.
- Radix: Progress.

**안내 띠**
- 쓰는 때: 화면 전체에 해당하는 알림(연결 끊김, 새 버전). 한 동작의 결과는 토스트를 씁니다.
- 구조: 본문 맨 위, 상태 점 + 문장 한 줄 + 오른쪽에 동작 버튼 하나(작은 버튼) + 닫기 아이콘 버튼.
- 치수: 최소 높이 44px(설정 행과 같음), 안쪽 8px 14px, 모서리 12px(담는 상자).
- 색: `--panel` 면, `--line` 테두리. 종류는 상태 점의 색과 모양으로 구분합니다(5.11). 면 전체를 색칠하지 않습니다.
- 접근성: `role="status"`(오류는 `role="alert"`). 닫기 버튼에 `aria-label`과 툴팁.
- Radix: 없음.

### 6.6 규칙에 없는 값이 필요할 때

1. 먼저 가장 가까운 기존 값으로 되는지 봅니다. 대부분 됩니다.
2. 정말 새 값이 필요하면 **토큰을 먼저 추가**합니다: `metis-tokens.css`와 이 문서 3장을 고치고, 14장에 이유를 적습니다. 그 다음에 씁니다.
3. 컴포넌트 안에 값을 직접 쓰고 넘어가지 않습니다.
4. 원칙(2장)을 바꿔야 하는 경우에는 멈추고 사람에게 묻습니다.

## 7. 새 화면을 만드는 규칙

새 화면은 아래 틀 중 하나로 만듭니다. 틀에 없는 배치를 새로 짜지 않습니다.

### 7.1 목록 화면 (레시피, 스킬, 스케줄러와 같은 종류)

```
[큰 제목]                          [검색 칸] [기본 버튼] [주요 버튼]
[설명 한 줄, --mute]

[카드: 행 묶음]
  이름 / 설명                      [작은 버튼] [토글] [⋯]
```

- 안쪽 최대 폭 920px, 가운데 정렬. 구역 사이 20px.
- 주요 버튼은 하나(만들기). 나머지는 기본 버튼.
- 행의 동작이 둘을 넘으면 ⋯ 메뉴에 모읍니다.
- 항목이 없으면 같은 자리에 빈 상태 카드.
- 검색은 오른쪽 위 검색 칸. "Ctrl+F로 검색" 같은 안내 문장을 쓰지 않습니다.

### 7.2 격자 화면 (채팅 기록과 같은 종류)

- 안쪽 최대 폭 1100px. 날짜나 종류별로 묶고, 묶음 제목은 11px 600 `--mute`.
- 카드 최소 폭 260px. 카드에는 제목, 보조 글자 한두 줄, ⋯ 메뉴.
- 여러 개를 고르는 화면이면 카드에 체크 상자를 두고, 하나라도 고르면 목록 위에 "N개 선택됨" 줄을 보여 줍니다.

### 7.3 설정 화면

```
[큰 제목]
[그룹 제목, 11px 600]
[카드: 행 묶음]
  이름 / 설명                      [컨트롤 하나]
```

- 안쪽 최대 폭 760px. "분류 → 그룹 제목 → 카드 → 행" 구조.
- 행 하나에 컨트롤 하나. 종류는 5.3의 표로 고릅니다.
- 숫자 입력 뒤에는 단위를 적습니다.
- 주의할 내용은 색 상자 대신 상태 점과 한 줄 안내로.
- 새 설정 분류를 만들면 사이드바 설정 목록에 아이콘과 함께 넣습니다.

### 7.4 창(모달)

- 입력을 받는 창: 제목, 입력들(라벨 위, 입력 아래, 사이 14px), 버튼 줄.
- 확인 창: 제목(무엇을 하는지), 설명 한두 문장(되돌릴 수 없으면 그렇다고), 버튼 줄(취소, 위험 버튼).
- 되돌릴 수 없는 동작(삭제, 초기화)은 반드시 확인 창을 거칩니다. `alert`, `confirm`을 쓰지 않습니다.
- 필수 입력이 비면 창을 닫지 않고 토스트로 알립니다.
- 창 위에 창을 다시 띄우지 않습니다.

### 7.5 알림을 고르는 법

| 상황 | 쓰는 것 |
|---|---|
| 방금 한 동작의 결과 | 토스트 |
| 되돌릴 수 없는 동작 전 | 확인 창 |
| 화면 전체에 해당하는 상태 | 안내 띠(6.5) |
| 한 항목의 상태 | 상태 점과 보조 글자 |
| 입력이 잘못됨 | 그 입력 아래 `--danger` 보조 글자 |

## 9. 문구

- 버튼은 **하는 일을 동사로** 씁니다: "저장", "삭제", "가져오기". "확인", "예"를 쓰지 않습니다.
- 다른 화면이나 창을 여는 버튼은 끝에 말줄임표: "가져오기…", "레시피 생성…". 바로 실행되는 버튼에는 붙이지 않습니다.
- 버튼은 2~6자, 창 제목은 15자 안쪽.
- 설명은 한 문장, 해요체가 아닌 합니다체("저장합니다").
- 빈 상태: 제목은 지금 상태("저장된 레시피가 없습니다"), 설명은 다음에 할 일.
- 오류: 무슨 일이 일어났는지와 할 수 있는 일을 한 문장씩. 사용자를 탓하지 않습니다.
- 확인 창: 되돌릴 수 없으면 그렇다고 적습니다.
- 문구를 코드에 직접 쓰지 않고 번역 파일에 넣습니다. 한국어 외 언어도 깨지지 않게 합니다.

## 10. 접근성

- 누를 수 있는 것은 모두 `button`이거나 Radix 부품. `div`에 클릭을 달지 않습니다.
- 키보드 포커스는 3.5px `--ring` 외곽선. 포커스 표시를 없애지 않습니다.
- 역할: 토글 `switch`, 선택 카드 `radio`, 체크 상자 `checkbox`, 창 `dialog`, 토스트 `status`. 접이식 구역과 도구 호출 행에는 `aria-expanded`.
- 아이콘만 있는 버튼에는 `aria-label`. 상태 점에는 상태 이름.
- 색만으로 구분하지 않습니다.
- 글자 대비 4.5:1 이상, 아이콘과 컨트롤 경계 3:1 이상.
- OS 설정을 따릅니다: 움직임 줄이기(`prefers-reduced-motion`), 고대비(`prefers-contrast`).
- 글자 크기 설정(작게 12px, 기본 13px, 크게 14.5px)을 바꿔도 배치가 깨지지 않아야 합니다.

## 11. 구현 (React, TypeScript, Tailwind, Radix, Electron)

### 11.1 원칙

- **기존 컴포넌트를 고쳐 씁니다.** 같은 역할의 컴포넌트를 새로 만들어 병행하지 않습니다.
- **공용 컴포넌트를 한 곳에 둡니다.** 버튼, 입력, 토글, 메뉴 같은 것은 저장소의 공용 UI 폴더(예: `components/ui`)에 하나씩만 있고, 화면은 그것을 가져다 씁니다. 화면 파일 안에서 버튼 모양을 Tailwind 클래스로 다시 짜지 않습니다.
- 종류(기본, 주요, 위험)는 컴포넌트의 prop으로 고릅니다. 저장소가 이미 쓰는 방식(예: `cva`, `clsx`, `tailwind-merge`)을 따르고, 없는 도구를 새로 넣지 않습니다.

### 11.2 토큰을 Tailwind에 연결

1. 저장소의 테마 구현을 먼저 읽습니다. 이미 CSS 변수와 Tailwind 색 이름이 있으면 **그 변수의 값을 3.1에 맞춰 바꾸고**, 없는 토큰만 추가합니다.
2. 대응 관계를 `docs/design/TOKEN_MAP.md`에 표로 적습니다(이 문서의 토큰 ↔ 저장소 변수 ↔ Tailwind 클래스). 이후 작업은 이 표를 따릅니다.
3. Tailwind 버전을 `package.json`에서 확인하고 그 버전의 방식을 씁니다.

기존 체계가 없을 때의 기본 이름:

| 토큰 | Tailwind 색 이름 | 예 |
|---|---|---|
| `--bg` / `--side` / `--panel` | `surface` / `side` / `panel` | `bg-surface` |
| `--text` / `--text2` / `--mute` | `ink` / `ink2` / `mute` | `text-ink` |
| `--line` | `line` | `border-line` |
| `--fill` / `--fill2` / `--fill3` / `--group` | `fill` / `fill2` / `fill3` / `group` | `bg-fill hover:bg-fill2 active:bg-fill3` |
| `--accent` / `--atext` / `--soft` | `accent` / `accent-ink` / `accent-soft` | `bg-accent` |
| `--btn` / `--btn-ink` | `btn` / `btn-ink` | `bg-btn text-btn-ink` |
| `--sel` / `--hover` | `sel` / `hover` | `bg-sel` |
| `--ok` / `--warn` / `--danger` / `--dsoft` | `ok` / `warn` / `danger` / `danger-soft` | `text-danger bg-danger-soft` |

Tailwind 4 (CSS에서 설정):

```css
@import "tailwindcss";
@import "./metis-tokens.css";

@theme inline {
  --color-surface: var(--bg);
  --color-side: var(--side);
  --color-panel: var(--panel);
  --color-ink: var(--text);
  --color-ink2: var(--text2);
  --color-mute: var(--mute);
  --color-line: var(--line);
  --color-fill: var(--fill);
  --color-fill2: var(--fill2);
  --color-fill3: var(--fill3);
  --color-accent: var(--accent);
  --color-accent-ink: var(--atext);
  --color-accent-soft: var(--soft);
  --color-btn: var(--btn);
  --color-btn-ink: var(--btn-ink);
  --color-danger: var(--danger);
  --color-danger-soft: var(--dsoft);
  /* 나머지 토큰도 같은 방식으로 */
}
```

Tailwind 3 (`tailwind.config`에서 설정):

```ts
export default {
  theme: {
    extend: {
      colors: {
        surface: 'var(--bg)', side: 'var(--side)', panel: 'var(--panel)',
        ink: 'var(--text)', ink2: 'var(--text2)', mute: 'var(--mute)', line: 'var(--line)',
        fill: 'var(--fill)', fill2: 'var(--fill2)', fill3: 'var(--fill3)',
        accent: { DEFAULT: 'var(--accent)', ink: 'var(--atext)', soft: 'var(--soft)' },
        btn: { DEFAULT: 'var(--btn)', ink: 'var(--btn-ink)' },
        danger: { DEFAULT: 'var(--danger)', soft: 'var(--dsoft)' },
      },
    },
  },
};
```

- Tailwind 기본 색(`bg-blue-500`, `text-gray-400` 등)과 임의 색(`bg-[#123456]`)을 쓰지 않습니다.
- 글자 크기는 `text-[13px]`처럼 3.3의 값만 씁니다. 저장소에 크기 이름이 있으면 그 이름을 3.3에 맞춥니다.
- 반투명 토큰(`--fill` 등)에는 Tailwind의 불투명도 수식(`bg-fill/50`)을 쓰지 않습니다.

### 11.3 Radix 상태와 4장의 대응

Radix 부품은 상태를 속성으로 내보냅니다. 클래스를 조건으로 바꾸지 말고 속성으로 스타일을 잡습니다.

| 4장의 상태 | Radix 속성 | Tailwind 예 |
|---|---|---|
| 켜짐(토글, 체크) | `data-state="checked"` | `data-[state=checked]:bg-accent` |
| 선택됨(구간 선택, 탭) | `data-state="on"` / `"active"` | `data-[state=on]:bg-panel` |
| 열림(메뉴가 붙은 버튼, 접이식) | `data-state="open"` | `data-[state=open]:bg-accent-soft` |
| 메뉴 항목 올림·키보드 이동 | `data-highlighted` | `data-[highlighted]:bg-fill2` |
| 쓸 수 없음 | `data-disabled` | `data-[disabled]:opacity-[0.42]` |
| 키보드 포커스 | `:focus-visible` | `focus-visible:outline-[3.5px]` |

- 메뉴 항목은 `:hover`가 아니라 `data-highlighted`로 잡습니다. 그래야 키보드로 옮길 때도 같은 표시가 납니다.
- 툴팁은 `Tooltip.Provider`에 `delayDuration={900}`.
- 저장소의 Radix 불러오는 방식(`radix-ui` 한 묶음 또는 `@radix-ui/react-*`)을 그대로 따릅니다.

### 11.4 Electron에서 확인할 것

- **글꼴**: Inter, Noto Sans KR, Sora, JetBrains Mono를 앱에 함께 넣습니다. 인터넷에서 불러오지 않습니다.
- **창 끌기**: 타이틀바는 `-webkit-app-region: drag`, 그 안의 버튼은 `no-drag`. 기존 구현을 유지합니다.
- **창 컨트롤**: Windows 방식(오른쪽 위)을 유지합니다.
- **입력창 자동 높이**: 시안은 `field-sizing: content`를 씁니다. 앱의 Electron(Chromium) 버전이 지원하지 않으면 기존의 높이 조절 코드를 씁니다.
- `color-mix()`를 지원하지 않는 버전이면 `--ring`을 `rgba()` 값으로 바꿔 적습니다.
- 시스템 테마 변화(`prefers-color-scheme`)와 고대비(`prefers-contrast`)에 반응하는지 확인합니다.

### 11.5 쌓임 순서 주의 (메뉴가 눌리지 않는 문제를 막는 규칙)

메뉴를 품고 있는 요소(카드, 행, 입력창, 화면 영역)에는 아래를 **쓰지 않습니다**. 쓰면 그 안의 메뉴가 가림막 아래로 내려가 눌리지 않습니다.

- `transform`, `filter`, `backdrop-filter`, 1 미만의 `opacity`
- 끝난 뒤에도 값이 남는 애니메이션(`animation-fill-mode: forwards`)

Radix의 Portal로 메뉴를 `body`에 붙이면 이 문제가 없습니다. 메뉴, 팝오버, 창, 툴팁은 Portal을 씁니다.

## 12. 검사

### 12.1 자동 검사

```bash
node scripts/design-check.mjs <UI 소스 폴더>
```

| 규칙 | 잡는 것 | 수준 |
|---|---|---|
| `color-literal` | 색상 값 직접 쓰기(`#fff`, `rgb()`) | 오류 |
| `tw-palette` | Tailwind 기본 색(`bg-blue-500`) | 오류 |
| `gradient` | 그라데이션 | 오류 |
| `backdrop-blur` | 반투명 유리 효과 | 오류 |
| `light-weight` | 가는 글자 굵기 | 오류 |
| `font-size` | 단계 밖의 글자 크기 | 오류 |
| `native-select` | `<select>` | 오류 |
| `native-dialog` | `alert()`, `confirm()` | 오류 |
| `tw-black-white` | `text-white`, `bg-black` | 알림 |
| `click-on-div` | `div`/`span`의 `onClick` | 알림 |

- 토큰 정의 파일(경로에 `tokens`, `theme`, `tailwind.config`가 든 파일)에서는 색상 값을 쓸 수 있습니다. `--allow=`로 바꿉니다.
- 꼭 필요한 예외는 그 줄에 `design-check-ignore`와 이유를 주석으로 적습니다.
- **기존 코드에 위반이 많을 때**: 처음 한 번 `--baseline=scripts/design-baseline.json --update-baseline`으로 현재 상태를 기록하고, 이후에는 `--baseline=scripts/design-baseline.json`으로 돌립니다. 기록보다 **늘어난** 위반만 실패합니다. 화면을 고칠 때마다 기준선을 다시 기록해 줄여 나갑니다.
- `package.json`의 `scripts`에 `"design:check"`로 넣고, 린트와 함께 돌립니다.
