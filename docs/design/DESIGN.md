# Metis 디자인 시스템 (DESIGN.md)

Metis 데스크탑 앱의 화면을 만들고 고칠 때 따르는 **단일 기준 문서**입니다.
지금 있는 화면뿐 아니라 **앞으로 추가될 화면과 컴포넌트**도 이 문서의 규칙으로 만듭니다.

- 판: 3차 (2026-11-20). 달라진 점은 14장에 있습니다.
- 앱 구성: React, TypeScript, Tailwind CSS, Radix UI, Vite, Electron (Windows 배포)
- 함께 있는 파일: `ui/metis-tokens.css`(토큰 값), `ui/metis-components.css`(컴포넌트 스타일의 참조 구현), `ui/gallery.html`(컴포넌트 견본), `metis-final-prototype.html`(보기용 시안), `assets/`(로고), `scripts/design-check.mjs`(자동 검사)

## 0. 읽는 법

| 하려는 일 | 읽을 곳 |
|---|---|
| 기존 화면을 이 디자인으로 바꾸기 | 1 → 3 → 4 → 5 → 8 → 11 |
| **새 컴포넌트 만들기** | **6** → 3 → 4 → 5 |
| **새 화면 만들기** | **7** → 6 → 5 |
| 문구 쓰기 | 9 |
| 끝났는지 확인하기 | 12 |

**무엇이 기준인가**

1. **이 문서가 규칙입니다.** 완료 여부는 이 문서(와 12장의 검사)로 판단합니다.
2. **토큰 값의 원본은 `ui/metis-tokens.css`입니다.** 이 문서 3장의 표는 그 파일에서 만들어 붙인 것입니다. 둘이 다르면 토큰 파일이 맞고, 이 문서를 고칩니다.
3. **`ui/metis-components.css`는 이 문서 4~5장을 CSS로 옮긴 참조 구현**이고, `ui/gallery.html`은 그것을 눌러 볼 수 있는 견본입니다. 컴포넌트의 값이 궁금하면 여기서 봅니다. 이 문서와 다르면 이 문서가 맞습니다(11.6).
4. **시안은 그림입니다.** 규칙이 어떻게 보이는지 확인하는 용도입니다. 시안과 이 문서가 다르면 이 문서를 따르고, 차이를 보고에 적습니다. 시안의 CSS는 여러 겹으로 덮어쓴 것이어서 값을 읽어 옮기지 않습니다. 값은 이 문서와 토큰 파일에서만 가져옵니다.
5. 이 문서 안에서 규칙이 부딪치면 **원칙(2장) → 토큰(3장) → 상태(4장) → 컴포넌트(5장) → 화면(8장)** 순서로 따릅니다.
6. 이 문서에 없는 것은 6.6을 따릅니다. 지어내지 않습니다.

## 1. 범위

**바꾸는 것**
- 색, 글자, 간격, 모서리, 컨트롤의 모습과 상태 표현
- 타이틀바와 사이드바의 배치
- 8장에 "변경"으로 적은 화면별 정리 항목
- 접근성 보완(10장): 포커스 표시, 역할과 이름, 키보드 조작

**바꾸지 않는 것**
- 화면 종류와 메뉴 구성, 설정 항목의 종류와 의미
- 기능, 데이터와 설정의 저장 방식과 **저장 시점**, 백엔드와의 통신
- 테마 선택지 4개(라이트, 다크, Aura, 시스템)와 **Aura 테마의 기존 색 값**(3.1)
- 번역 구조. 문구를 번역 파일로 옮기는 작업은 이 범위가 아닙니다(9장).
- 지원 창 크기. 최소 창 크기는 960 x 600px로 보고, 그보다 좁은 화면용 배치는 만들지 않습니다(8.1).

**모습과 동작의 경계**

이 문서에는 모습(스타일) 규칙과 동작 규칙이 함께 있습니다. 이미 만들어진 앱에 적용할 때는 아래처럼 나눕니다.

| 구분 | 해당하는 것 | 적용 |
|---|---|---|
| 모습 | 색, 글자, 간격, 모서리, 상태 표현, 배치, 컴포넌트의 생김새, 오류·알림을 보여 주는 자리(7.5) | 바로 적용 |
| 접근성 보완 | 포커스 표시, 역할과 이름, 키보드 조작, 포커스 이동(10.2, 10.3), 고대비와 움직임 줄이기(10.4) | 바로 적용 |
| **동작 변경** | 아래 목록. 앱이 지금 하는 일이 달라지는 것 | **기존 동작을 유지합니다.** 0단계 조사에서 현재 동작을 적고, 사람이 승인한 항목만 따로 적용합니다 |

동작 변경 목록(이 문서가 권하는 동작이지만 승인 없이는 바꾸지 않는 것):

1. 승인 카드에 바뀔 내용을 미리 보여 주기(5.13)
2. "이 채팅에서 항상 허용"의 범위와 해제 방법(5.13)
3. 실행 중에 Enter를 눌렀을 때의 처리(5.12)
4. 작성 중인 창을 닫을 때 확인하기(7.4)
5. 지금 확인 없이 지워지는 것에 확인 창 넣기(7.4)
6. 입력 값을 확인하는 때와 잘못된 값의 처리(7.4)
7. 여러 개를 골랐을 때 보이는 항목에만 적용하기(7.2)
8. 오류 카드의 "다시 시도", 최대 턴 도달 뒤 "계속"(5.13)
9. 창 너비 960~1240px에서 사이드 패널과 사이드바를 번갈아 보여 주기(8.1)
10. 13.2에 "넣지 않습니다"로 적힌 새 요소

위 항목의 **모습**(승인 카드의 생김새, 오류 문장의 자리와 색 등)은 "모습"에 속하므로 바로 적용합니다.

**"항목을 없애지 않는다"의 뜻**: 기능을 없애지 않는다는 뜻입니다. 화면에 늘어놓은 버튼을 ⋯ 메뉴 안으로 옮기는 것은 허용합니다(8.11). 옮긴 뒤에도 모든 동작에 닿을 수 있어야 합니다.

**시안을 볼 때 주의**
- 시안 파일 끝의 런타임 스크립트와 `<x-dc>`, `<sc-for>`, `<sc-if>` 태그는 시안 도구용입니다. 구조를 가져다 쓰지 않습니다.
- 시안의 클래스 이름(`.btn`, `.inp` 등)은 이 문서에서 컴포넌트를 가리키는 이름으로만 씁니다.
- 시안의 채팅, 레시피, 일정, 모델, 경로, 버전은 모두 꾸며 낸 예시입니다.
- 시안은 글꼴을 Google Fonts에서 불러옵니다(열면 외부 요청이 나갑니다). 앱은 글꼴을 함께 넣어 배포합니다(11.4).
- 시안에는 창 너비 900px 이하용 배치가 남아 있습니다. 구현하지 않습니다.

## 2. 원칙

컨셉은 **모노 톤의 평면 화면**이고, 입력과 컨트롤의 세부는 **Apple Human Interface Guidelines(HIG)** 의 방식을 참고했습니다. 창 조작과 대화 상자의 관례는 **Windows**를 따릅니다(10.5).

1. **모노 톤.** 화면은 무채색입니다. 주요 버튼도 먹색(라이트)이나 흰색(다크)입니다. 선택됨과 열림도 무채색으로 표시합니다.
2. **강조색을 쓰는 곳은 넷뿐입니다.** ① 켜진 토글·체크 상자·라디오 ② 포커스 링 ③ 진행 표시(진행 막대, 실행 중 표시, 진행 중 단계) ④ 링크 글자. 이 밖에는 쓰지 않습니다.
3. **평면.** 그라데이션, 발광, 반투명 유리 효과를 쓰지 않습니다. 그림자는 다른 것 위에 떠 있는 것(메뉴, 창, 채팅 입력창, 툴팁, 토스트, 선택 막대)에만 씁니다. 카드에는 없습니다.
4. **면으로 구분.** 사이드바·타이틀바는 `--side`, 본문은 `--bg`. 떠 있는 테두리 패널로 화면을 나누지 않습니다.
5. **누르는 것은 채움, 값을 넣거나 고르는 것은 채움과 경계선.** 버튼·태그는 옅은 채움(`--fill`)만 씁니다. 입력·드롭다운·체크 상자·라디오·토글은 채움에 `--ctl-line` 경계선을 더해 바탕과 3:1 이상으로 구분합니다.
6. **주요 버튼은 영역마다 하나까지.** 영역은 사이드바, 본문, 창 셋입니다. 사이드바의 "새 채팅", 본문의 만들기 버튼이나 전송 버튼, 창의 실행 버튼이 각각 그 영역의 주요 버튼입니다. 나머지는 기본, 고스트, 위험 버튼으로 낮춥니다.
7. **모든 누를 수 있는 것은 상태를 가집니다.** 기본, 올림, 누름, 포커스가 반드시 있습니다(4장).
8. **상태는 색과 모양을 함께.** 색만으로 구분하지 않습니다. 선택된 항목은 면 색에 더해 왼쪽 막대, 체크 표시, 굵기 중 하나가 함께 바뀝니다.
9. **움직임은 상태를 알릴 때만.** 꾸미는 움직임은 넣지 않습니다. "움직임 줄이기" 설정에서는 모두 끄되, 상태 표시 자체는 멈춘 모양으로 남깁니다(3.8).
10. **여러 동작은 메뉴 하나로.** 항목마다 아이콘을 늘어놓지 않고 ⋯ 메뉴에 모읍니다.

## 3. 토큰

색·크기·모서리·간격·층은 **토큰으로만** 씁니다. 컴포넌트에 값을 직접 쓰지 않습니다.
원본은 `metis-tokens.css`이고, Tailwind에 연결하는 방법은 11.2에 있습니다.

### 3.1 색

루트 요소의 `data-theme`(`light` | `dark` | `aura`)으로 정해집니다. 테마 설정이 "시스템"이면 `prefers-color-scheme`에 따라 `light` 또는 `dark`를 넣습니다. 처음 설치했을 때의 기본값은 앱의 기존 기본값을 유지합니다.
**앱에 이미 테마 변수 체계가 있으면 새 체계를 따로 만들지 않습니다.** 기존 변수의 값을 아래에 맞춰 바꾸고, 대응 관계를 `docs/design/TOKEN_MAP.md`에 적습니다(11.2).

- 반투명 값(`--fill` 계열, `--hover`, `--ctl-line`)은 어떤 면 위에 올려도 같은 단계로 보이게 하려는 것입니다. Tailwind의 불투명도 수식(`bg-control/50`)을 덧붙이지 않습니다.
- 강조색 글자는 `--accent`가 아니라 `--atext`를 씁니다(대비 때문).
- `--soft`는 예비입니다. 현재 화면에서는 쓰지 않습니다.
- 값을 바꿀 때는 10.1의 대비 기준을 다시 확인합니다.

**Aura 테마**: 현재 앱의 Aura 색 값을 **그대로 둡니다.** 이 문서는 Aura의 색을 정하지 않습니다. 새로 생긴 토큰(`--fill` 계열, `--ctl-line`, `--group`, `--ring` 등)은 Aura가 밝은 테마이므로 라이트 값을 물려받습니다. 물려받은 값이 Aura 바탕에서 10.1의 대비를 못 넘으면 그 토큰만 Aura용 값을 정하고 14장에 적습니다. 시안의 Aura는 확인 없이 그린 임시 값이며 `metis-tokens.css`에 넣지 않았습니다.

**어떤 색을 고를지**

| 쓰려는 곳 | 토큰 |
|---|---|
| 화면 바탕 | `--bg` (사이드바·타이틀바는 `--side`) |
| 카드, 창, 메뉴, 입력창 | `--panel` |
| 누르는 컨트롤의 면(버튼, 태그, 구간 선택) | `--fill` → 올림 `--fill2` → 누름 `--fill3` |
| 값을 넣거나 고르는 컨트롤의 경계선 | `--ctl-line` |
| 묶음 안의 옅은 면(선택 카드) | `--group` |
| 선택된 행, 선택된 카드 | `--sel` |
| 목록 행 올림(사이드바, 메뉴가 아닌 목록) | `--hover` |
| 구분선, 카드 테두리 | `--line` |
| 글자 | `--text` → 보조 `--text2` → 설명·자리 표시 `--mute` |
| 켜짐, 진행 | `--accent` (글자는 `--atext`) |
| 포커스 링 | `--ring` |
| 성공 / 주의 / 위험 | `--ok` / `--warn` / `--danger` (위험의 옅은 면은 `--dsoft`) |

### 3.2 글꼴

| 용도 | 글꼴 스택 |
|---|---|
| 화면 | `Inter, 'Noto Sans KR', 'Malgun Gothic', 'Segoe UI', system-ui, sans-serif` |
| 워드마크 "Metis" | `Sora, Inter, 'Segoe UI', sans-serif`, 굵기 600, 자간 -0.03em |
| 코드, 경로, 모델 이름 | `'JetBrains Mono', Consolas, ui-monospace, monospace`, 합자 끔 |

- 앱은 Windows에서 돌기 때문에 Inter(라틴)와 Noto Sans KR(한글)이 실제로 쓰이는 글꼴입니다. 둘 다 앱에 함께 넣습니다(11.4).
- 넣는 굵기: Inter 400·500·600·700, Noto Sans KR 400·500·600·700, Sora 600, JetBrains Mono 400·500·600. 600이 없으면 브라우저가 굵기를 흉내 내어 글자가 뭉개집니다.
- 시안의 CSS에는 Apple 계열 글꼴 이름이 앞에 남아 있습니다. 옮기지 않습니다.

### 3.3 글자 크기

단계는 아래 8개뿐입니다. 이 밖의 크기와 `em`·`rem` 배수는 쓰지 않습니다. 굵기는 400, 500, 600, 700만 씁니다.

| 이름 | 크기 / 줄 높이 | 굵기 | 쓰는 곳 |
|---|---|---|---|
| `display` 큰 제목 | 26 / 32px | 700 | 페이지 제목, 설정 분류 제목 |
| `title` 제목 | 22 / 26px | 700 | 버전 표시의 워드마크. 그 밖에는 예비 |

| `body` 본문 | 13px / 1.5 | 400 | 대화, 행 이름(500), 버튼(500, 주요 버튼 600), 입력 |

- 값은 px로 고정입니다. 받은 화면에는 글자 크기를 바꾸는 설정이 없습니다. 나중에 만든다면 글자만이 아니라 화면 전체의 배율로 적용합니다.

## 4. 상태 규칙

**누를 수 있는 모든 요소**에 아래 상태가 있어야 합니다. 새 컴포넌트도 이 표에서 값을 가져옵니다.

| 상태 | 누르는 컨트롤(버튼, 태그) | 값 컨트롤(입력, 드롭다운) | 목록 행(사이드바, 메뉴) | 주요 버튼 |
|---|---|---|---|---|
| 기본 | `--fill` | `--fill` + `--ctl-line` 1px 경계선 | 면 없음 | `--btn` 면, `--btn-ink` 글자 |
| 올림 | `--fill2` | 입력: 면은 그대로, 경계선이 `--mute`로 진해짐. 드롭다운: `--fill2` | `--hover` (메뉴 항목은 `--fill2`) | 불투명도 88% |
| 누름 | `--fill3`, 98% 크기 | - | `--sel` (메뉴 항목은 `--fill3`) | 98% 크기 |
| 키보드 포커스 | 2px `--ring` 외곽선, 바깥으로 2px 띄움 | `--panel` 면 + 2px `--ring` 외곽선(띄움 없음) | 2px `--ring` 외곽선 | 2px `--ring` 외곽선 |
| 선택됨 | `--fill3` 면 + `--ctl-line` 1px 경계선 + `--text` 글자(켜진 아이콘 버튼) | - | `--sel` 면 + 왼쪽 2px `--text` 막대 + 굵기 500 | - |
| 열림(메뉴가 붙은 버튼) | `--fill2` 면, `--text` 글자, 화살표 180도 | 같음 | - | - |
| 잘못된 값 | - | `--danger` 2px 경계선 + 아래에 오류 문장 | - | - |
| 쓸 수 없음 | 불투명도 42%, 누름 반응 없음 | 같음 | 같음 | 같음 |
| 처리 중 | 글자 앞에 회전 고리, 다시 누를 수 없음 | - | - | 같음 |

- 켜짐(토글, 체크 상자, 라디오)은 `--accent` 면입니다(5.3).
- **포커스 표시는 항상 `outline`으로 그립니다.** `box-shadow`로 그리면 Windows의 대비 테마에서 사라집니다. 입력 칸의 글자는 마우스로 눌러도 포커스 표시가 나타납니다.
- 입력 칸에 올렸을 때 면을 진하게 하지 않는 것은 자리 표시 글자의 대비(4.5:1)를 지키기 위해서입니다.
- 위험 동작은 `--dsoft` 면과 `--danger` 글자입니다. 올리면 면이 진해집니다. 위험 버튼을 주요 버튼 모양으로 만들지 않습니다.
- 올림은 마우스가 있을 때만(`@media (hover: hover)`) 적용합니다.
- **쓸 수 없는 버튼**: 왜 못 쓰는지 사용자가 알 수 있을 때만 씁니다(빈 입력창의 전송). 이유를 알기 어려우면 버튼을 살려 두고, 눌렀을 때 이유를 알려 줍니다. `disabled` 대신 `aria-disabled="true"`를 써서 키보드 포커스가 닿게 합니다.
- **평소에 흐리게 두는 요소**(행의 ⋯ 버튼, 구역 제목의 + 버튼, 답변 아래 동작)는 불투명도를 낮추지 않고 `--mute` 색으로 둡니다. 올리면 `--text`가 됩니다. 불투명도로 숨기면 대비 기준을 못 넘습니다.
- 설정 행 자체에는 올림 표시가 없습니다(행이 아니라 그 안의 컨트롤을 누르기 때문). 통째로 눌리는 카드(채팅 기록)는 올리면 테두리가 `--ctl-line`으로 진해집니다.
- Radix 컴포넌트에서는 상태를 `data-state`, `data-highlighted`, `data-disabled` 속성으로 잡습니다(11.3).

## 5. 컴포넌트

괄호 안은 시안의 클래스 이름입니다. "Radix"는 구현에 쓸 기본 부품입니다. 저장소에 같은 역할의 컴포넌트가 이미 있으면 그것을 고쳐 씁니다.

### 5.1 버튼 (`.btn`)

| 종류 | 모습 | 쓰는 곳 |
|---|---|---|
| 기본 | `--fill` 면, 글자 500 | 취소, 가져오기, 편집, 변경, 중지 |
| 주요 (`.pri`) | `--btn` 면, `--btn-ink` 글자, 600 | 새 채팅, 레시피 생성, 저장, 허용, 전송 |
| 위험 (`.danger`) | `--dsoft` 면, `--danger` 글자 | 삭제, 초기화, 버리고 닫기 |
| 고스트 (`.ghost`) | 면 없음, `--text2` 글자. 올리면 `--fill` | 거부, 선택 해제, 옵션 표시 |

- 높이 28px, 모서리 999px, 좌우 12px. 작은 버튼(`.sm`)은 24px, 12px 글자.
- 아이콘은 글자 앞에 16px, 사이 6px.
- 입력이 더 필요한 버튼은 이름 끝에 말줄임표를 붙입니다(9장).
- 아이콘만 있는 버튼(`.ibtn`)은 30px 원형이고, `aria-label`과 툴팁이 있어야 합니다.

### 5.2 입력 (`.inp`)

- 높이 28px, 모서리 8px, `--fill` 면, `--ctl-line` 1px 안쪽 경계선. 올리면 경계선이 `--mute`로 진해집니다.
- 포커스: `--panel` 면, 2px `--ring` 외곽선.
- 자리 표시 글자는 `--mute`(불투명도 100%)입니다.
- 검색 칸은 모서리 999px, 좌우 14px.
- 여러 줄 입력은 모서리 8px, 최소 높이 76px.
- 숫자 입력은 폭 112px, 오른쪽 정렬, 뒤에 단위를 보조 글자로.
- **비밀 값**(API 키, 토큰)은 `type="password"`로 가리고, 옆에 "보기"/"숨기기" 버튼을 둡니다(`aria-pressed`). 자동 완성을 끕니다.
- **폴더·파일 경로**는 입력 옆에 "찾아보기…" 버튼을 두어 운영체제의 선택 창을 엽니다.
- 라벨은 입력 위에 12px 600. 모든 입력에 보이는 라벨이나 `aria-label`이 있어야 합니다. 설명 글이 있으면 `aria-describedby`로 잇습니다.
- 오류는 7.4를 따릅니다.

### 5.3 선택 컨트롤

| 컨트롤 | 쓰는 때 | 모습 | Radix |
|---|---|---|---|
| 토글 (`.tgl`) | 켜고 끄기. 바로 적용됨 | 38x22. 꺼짐 `--fill3` 면 + `--ctl-line` 경계선, 켜짐 `--accent` 면. 손잡이 위치가 함께 바뀜 | Switch |
| 구간 선택 (`.seg`) | 선택지가 2~4개이고 이름이 모두 짧을 때(각 6자 이내) | 캡슐. 선택 칸은 `--segsel` 면 + `--ctl-line` 1px 테두리 + 굵기 600 | RadioGroup 또는 ToggleGroup(single) |
| 드롭다운 (`.dd`) | 그 밖의 하나 고르기. 목록이 늘 수 있으면(언어, 모델) 개수와 상관없이 드롭다운 | 28px 캡슐, `--ctl-line` 경계선, 오른쪽 화살표 | Select |
| 선택 카드 (`.opt`) | 선택지마다 설명이 필요할 때 | `--group` 면. 선택되면 `--sel` 면 + 채워진 라디오 | RadioGroup |
| 체크 상자 (`.cbx`) | 목록에서 여러 개 고르기 | 16px, `--panel` 면 + `--ctl-line` 경계선. 켜짐 `--accent` 면 + 흰 체크 | Checkbox |
| 목록에서 고르기 | 창 안에서 긴 목록 중 하나(모델, 레시피) | 행 목록. 선택된 행은 왼쪽 체크 표시 + 굵기 600 | RadioGroup |

- 운영체제 기본 셀렉트(`<select>`)를 쓰지 않습니다.
- 켜고 끄는 설정에 체크 상자를 쓰지 않습니다. 토글을 씁니다.
- 라디오 묶음(구간 선택, 선택 카드, 목록에서 고르기)은 Tab으로 묶음에 한 번 들어가고, 화살표로 선택을 옮깁니다(10.3).

### 5.4 메뉴와 팝오버 (`.menu`)

둘을 구분합니다. 역할과 키보드 동작이 다릅니다.

| | 메뉴 | 팝오버 |
|---|---|---|
| 내용 | 동작 목록(⋯ 메뉴), 값 고르기(드롭다운) | 검색 칸, 토글, 여러 구역이 섞인 것(입력창의 모델·프로젝트·익스텐션) |
| 역할 | `menu` + `menuitem` (값 고르기는 Select의 `listbox`) | `dialog` |
| Radix | DropdownMenu, Select | Popover |
| 닫힘 | 항목을 고르면 닫힘 | 값을 골라도 열려 있을 수 있음(토글) |

공통:
- `--panel` 면, 모서리 12px, 안쪽 4px, 그림자 `--pop`. 최소 폭 200px.
- 항목: 최소 높이 28px, 모서리 8px, 좌우 10px. 올림(키보드 이동 포함) `--fill2`.
- 선택된 항목은 왼쪽 체크 표시로 알립니다. 면을 칠하지 않습니다.
- 위험 항목은 `--danger` 글자, 올리면 `--dsoft` 면. 목록 맨 아래에 둡니다.
- 한 번에 하나만 열립니다. 바깥을 누르거나 Esc를 누르면 닫히고, **포커스는 연 버튼으로 돌아갑니다.**
- 열리면 포커스가 안으로 들어갑니다(검색 칸이 있으면 검색 칸, 없으면 선택된 항목이나 첫 항목). 화살표 위아래, Home, End로 옮깁니다.
- 연 버튼에는 `aria-haspopup`과 `aria-expanded`가 있고, 열려 있는 동안 "열림" 상태로 보입니다.
- 채팅 입력창의 팝오버는 위로, 그 밖은 아래로 열립니다. 화면 밖으로 나가면 반대쪽으로 뒤집습니다(Radix의 기본 동작을 끄지 않습니다).
- 항목 강조는 `:hover`가 아니라 `data-highlighted`로 잡습니다.
- **오른쪽 클릭 메뉴**: 목록의 항목(채팅, 레시피, 일정, 프로젝트)을 오른쪽 클릭하면 그 항목의 ⋯ 메뉴와 같은 내용이 열립니다(Radix ContextMenu). 시안에는 없습니다.

### 5.5 카드와 행 (`.card`, `.row`)

- 카드: `--panel` 면, `--line` 1px 테두리, 모서리 12px, 그림자 없음.
- 행 묶음: 카드 안에 행을 쌓고 행 사이에 `--line` 1px. 행은 최소 44px, 안쪽 8px 14px.
- 행: 왼쪽에 이름(13px 500)과 설명(11px `--mute`). 오른쪽에 **값을 바꾸는 컨트롤 하나**. 여기에 보조 동작으로 작은 버튼 하나와 ⋯ 메뉴 하나까지 더할 수 있습니다(예: 단축키 행의 키 조합 + "변경…" + 토글). 그보다 많으면 ⋯ 메뉴로 옮깁니다.
- 격자 카드(채팅 기록, 익스텐션): 최소 폭 260px.
- 카드나 행을 통째로 움직이는 효과(이동, 기울임, 들어 올림)는 넣지 않습니다.

### 5.6 사이드바 항목

- 내비게이션 항목(`.nav`): 높이 30px, 모서리 8px, 아이콘 16px(`--text2`)과 이름. 현재 화면은 `--sel` 면 + 왼쪽 2px `--text` 막대 + 굵기 500, `aria-current="page"`.
- 구역 제목(`.sec`): 11px 600 `--mute`, 접힘 화살표, 오른쪽에 + 버튼(`--mute`, 올리면 `--text`).
- 채팅 행(`.srow`): 한 줄. 제목(넘치면 말줄임)과 시간. 실행 중이나 승인 대기일 때만 앞에 상태 표시(5.11).
- 채팅 구역이 접혀 있는데 승인을 기다리는 채팅이 있으면, 구역 제목 옆에 "승인 대기 N"을 표시합니다. 접혀 있어도 놓치지 않게 하려는 것입니다.
- 프로젝트 행: 폴더 아이콘, 이름, 채팅 수. 누르면 아래에 채팅이 들여쓰기로 나옵니다.
- **사이드바가 보이지 않을 때**(접었거나, 좁은 창에서 사이드 패널에 자리를 내줬을 때, 8.1)는 타이틀바의 사이드바 버튼 옆에 "새 채팅" 아이콘 버튼이 나타납니다. 승인을 기다리는 채팅이 있으면 사이드바 버튼 모서리에 승인 대기 표시(5.11)가 붙습니다.
- 설정 화면에서는 사이드바가 설정 분류 목록으로 바뀌고, 사이드바 버튼은 쓸 수 없음 상태가 됩니다(접으면 분류를 옮길 수 없기 때문).
- Radix: Collapsible(접이식 구역).

### 5.7 태그 (`.tag`)

높이 24px 캡슐, `--fill` 면, 12px. 누를 수 있는 태그는 `button`이고 올리면 `--fill2`, 누르면 `--fill3`. 메뉴를 여는 태그는 끝에 아래 화살표가 있습니다. 누를 수 없는 태그(이미 정해진 프로젝트)는 `span`이고 화살표가 없습니다. 채팅 입력창의 태그는 28px.

### 5.8 탭 (`.tab`)

12px, 높이 42px. 선택된 탭은 `--text` 글자 600과 아래 2px 선. 역할은 `tablist` + `tab`(`aria-selected`), 화살표 좌우로 옮깁니다. Radix: Tabs.

### 5.9 창(모달)

- 가운데, 폭 최대 540px, 모서리 20px, 뒤는 `--scrim`(타이틀바는 덮지 않음). `role="dialog"`, `aria-modal="true"`, 제목으로 이름을 붙입니다.
- 제목 줄(15px 600, 오른쪽에 닫기 아이콘 버튼), 본문, 버튼 줄.
- **버튼 줄**: 오른쪽 정렬. **주요 동작이 왼쪽, 취소가 오른쪽**입니다(Windows 관례). 그 창에만 있는 위험 동작(제공업체 삭제)은 맨 왼쪽에 떨어뜨립니다.
- 열리면 첫 입력(입력이 없으면 버튼 줄의 첫 버튼)으로 포커스가 갑니다. Tab은 창 안에서만 돕니다. 닫히면 창을 연 버튼으로 포커스가 돌아갑니다.
- Esc, 닫기 버튼, 가림막을 누르면 창이 닫힙니다. 작성 중인 내용이 있으면 7.4의 확인을 거칩니다. **확인 창은 가림막을 눌러도 닫히지 않습니다.** 버튼으로만 답합니다.
- **창이 떠 있는 동안 창 밖은 눌리지 않습니다.** 타이틀바의 앱 버튼(사이드바, 새 채팅, 패널)도 포함입니다. 예외는 창 끌기와 창 컨트롤(최소화, 최대화, 닫기)뿐입니다. Radix Dialog는 창 밖을 모두 막으므로, 창 컨트롤을 직접 그리는 앱이라면 창 컨트롤이 막히지 않는지 확인하고, 막히면 창 컨트롤을 Dialog가 막는 영역 밖(별도 루트)에 둡니다. `titleBarOverlay`로 운영체제의 컨트롤을 쓰면 해당 없습니다.
- 창 위에 창을 다시 띄우지 않습니다. 확인이 필요하면 같은 창의 내용을 확인 문장으로 바꿉니다.
- Radix: Dialog, AlertDialog(확인 창).

### 5.10 토스트와 툴팁

**토스트**
- 위치는 **타이틀바 아래 가운데**(위에서 56px)입니다. 아래에 두면 채팅 입력창과 선택 막대를 가립니다.
- 캡슐, 안쪽 8px 16px, `--text` 면과 `--bg` 글자, 그림자 `--pop`. `role="status"`. 포커스를 가져가지 않습니다.
- 한 번에 하나만 보입니다. 새 토스트가 오면 앞의 것을 바꿉니다.
- 보이는 시간: 2.6초. 20자를 넘으면 한 글자에 0.06초씩 더해 최대 8초.
- **토스트로 알려도 되는 것**: 방금 한 동작이 됐다는 사실("저장했습니다"), 놓쳐도 문제없는 안내.
- **토스트로 알리면 안 되는 것**: 입력 오류(7.4), 사용자가 뭔가 해야 하는 오류(안내 띠나 대화 안의 오류 카드), 되돌릴 수 없는 일의 확인(확인 창).
- 토스트 안에 버튼을 넣지 않습니다.

**툴팁**
- **아이콘만 있는 버튼에는 반드시** 붙입니다.
- 글자가 있는 버튼에는 붙이지 않습니다. 예외는 그 글자가 **값만 보여 주고 무엇인지는 알려 주지 않을 때**입니다(입력창의 모델 이름 태그 → 툴팁 "모델").
- 창 컨트롤(최소화, 최대화, 닫기)에는 붙이지 않습니다.
- 11px, 모서리 5px, 안쪽 4px 8px, `--tip` 면과 `--tip-ink` 글자, 0.9초 뒤 표시. 키보드 포커스에서는 바로 표시.
- 단축키가 있으면 이름 뒤에 함께 적습니다(예: 새 채팅 Ctrl+T). 단축키는 사용자가 바꿀 수 있으므로 **설정에 저장된 값을 읽어** 표시합니다.
- 툴팁은 이름을 대신하지 않습니다. `aria-label`은 따로 있어야 합니다.
- Radix: Tooltip(`delayDuration` 900).

### 5.11 상태 표시 (8px)

색과 모양이 함께 다릅니다. 색을 못 봐도 구분됩니다.

| 상태 | 색 | 모양 |
|---|---|---|
| 실행 중 | `--accent` | 한쪽이 끊어진 고리, 회전 |
| 승인 대기 | `--warn` | 둥근 사각(모서리 2px) |
| 완료, 켜짐 | `--ok` | 채워진 원 |
| 꺼짐 | 테두리만 | 빈 원 |
| 오류 | `--danger` | 마름모 |

상태 표시에는 `role="img"`와 상태 이름 `aria-label`을 붙입니다. 옆에 같은 뜻의 글자가 있으면 `aria-hidden="true"`로 둡니다.

### 5.12 채팅 입력창 (`.composer`)

- `--panel` 면, 모서리 20px, 1px `--ctl-line` 실선과 그림자. 글을 쓰는 칸에 포커스가 있으면 실선이 2px `--ring`으로 바뀝니다.
- 내용만큼 높이가 늘어납니다(최소 2줄, 최대 약 9줄, 그 뒤는 스크롤).
- 아래 줄: 모델 태그, 프로젝트 태그, (여백), 익스텐션 태그("익스텐션 N"), 첨부, 전송. 메뉴를 여는 태그에는 모두 아래 화살표가 있습니다.
- **진행 중인 채팅의 프로젝트는 바꿀 수 없으므로** 누를 수 없는 태그(`span`, 화살표 없음)로 보여 줍니다. 새 채팅에서만 고를 수 있는 버튼입니다.
- 전송 버튼: 주요 버튼(원형 28px, 아이콘만). 비어 있으면 쓸 수 없음 상태(`aria-disabled="true"`).
- **실행 중**: 전송 버튼이 중지 버튼으로 바뀝니다. 중지 버튼은 기본 버튼 모양입니다(주요 버튼이 아님). 실행 중에도 글은 쓸 수 있습니다. 실행 중에 Enter를 눌렀을 때의 처리는 앱의 기존 동작을 유지합니다(1장의 동작 변경 3번). 어떤 방식이든 **쓴 글이 사라지면 안 됩니다.** 시안은 보내지 않고 "실행이 끝난 뒤에 보낼 수 있습니다"를 알립니다.
- 포커스가 들어가면 아래에 단축키 안내가 나타납니다(Enter 전송, Shift+Enter 줄바꿈, / 스킬 부르기).
- **첨부**: 붙인 파일은 글 쓰는 칸 위에 칩으로 쌓입니다(파일 이름, 크기, 지우기 × 버튼). 높이 24px, 모서리 8px.
- **/ 메뉴**: 글 맨 앞에서 /를 치면 입력창 위로 스킬 목록 팝오버가 열립니다. 치는 대로 걸러지고, 화살표로 옮기고, Enter로 고르고, Esc로 닫습니다. 5.4의 모습을 씁니다. 시안에는 없습니다.

### 5.13 대화 요소

대화 영역은 `role="log"`입니다. 새 내용이 화면 낭독기에 차례로 읽힙니다.

- **사용자 말풍선**: 오른쪽 정렬, 최대 폭 86%, `--bubble` 면, 모서리 16 16 5 16px, 안쪽 8px 14px.
- **답변**: 테두리 없는 본문, 최대 68자 폭.
- **답변 속 서식**(마크다운):

  | 요소 | 모습 |
  |---|---|
  | 제목 1 / 2 / 3 | 17px 600 / 15px 600 / 13px 600. 위 16px, 아래 8px |
  | 문단, 목록 | 13px / 1.5. 문단 사이 8px. 목록 들여쓰기 20px |
  | 굵게, 기울임 | 600, 기울임 |
  | 링크 | `--atext` + 밑줄. 외부 링크는 기본 브라우저에서 엽니다 |
  | 줄 안 코드 | 코드 글꼴 12px, `--fill` 면, 모서리 5px, 좌우 4px |
  | 인용 | 왼쪽 2px `--line` 막대, `--text2` 글자, 왼쪽 여백 12px |
  | 표 | `--line` 1px 가로선만. 머리글 12px 600 `--mute`. 칸 안쪽 6px 10px. 넘치면 표만 가로 스크롤 |
  | 구분선 | `--line` 1px, 위아래 12px |

- **코드 블록**: `--line` 테두리, 모서리 8px. 머리 줄에 언어 이름(12px 코드 글꼴)과 복사 아이콘 버튼. 본문은 `--code` 면, 코드 글꼴 12px, 줄바꿈하지 않고 가로 스크롤. 구문 색칠은 저장소의 기존 방식을 유지하되 색은 토큰으로 바꿉니다.
- **바뀐 내용(diff)**: 줄마다 줄 번호, 부호(+, −), 내용. 추가된 줄은 `--add-bg` 면과 `--add-tx` 글자, 지운 줄은 `--del-bg` 면과 `--del-tx` 글자. **색에 더해 +와 − 부호가 항상 있습니다.** 머리 줄(@@)은 `--mute`.
- **할 일 카드**: 제목 줄에 진행 수(1/3). 완료는 `--ok` 원에 체크, 진행 중은 회전 고리, 예정은 빈 원.
- **도구 호출 카드**: 행마다 펼침 화살표, 익스텐션 이름, 호출 내용(코드 글꼴), 결과 요약. 누르면 출력이나 바뀐 내용이 펼쳐집니다(`aria-expanded`).
- **승인 카드**:
  - `--warn` 1px 테두리. 맨 위에 승인 대기 표시와 "승인을 기다리는 중입니다"(`role="status"`).
  - 무엇을 하려는지(호출 내용, 코드 글꼴), **파일을 바꾸는 일이면 바뀔 내용을 diff로 미리 보여 줍니다**, 그리고 왜 묻는지 한 문장.
  - 버튼 셋: "허용"(주요), "이 채팅에서 항상 허용"(기본), "거부"(고스트).
  - **"이 채팅에서 항상 허용"**: 그 채팅에서, 해제할 때까지, 도구를 쓸 때마다 묻던 승인을 건너뜁니다. 다른 채팅과 설정의 기본 모드는 바뀌지 않고, 그 채팅의 모드 이름도 바뀌지 않습니다. 누르면 토스트로 알리고, 채팅 헤더의 모드 태그가 "수동 · 항상 허용"처럼 됩니다. **채팅의 ⋯ 메뉴에 "항상 허용 해제"가 생기고**, 누르면 다시 묻습니다.
  - 앱에 이미 "항상 허용"이 있고 범위가 다르면(예: 그 도구만, 모든 채팅) **앱의 범위를 유지하고 버튼 이름을 그 범위에 맞춥니다**("이 도구 항상 허용" 등). 범위를 이름에 드러내는 것이 규칙입니다.
  - 기다리는 동안: 진행 막대와 점 3개를 숨기고, 진행 중 단계의 고리를 멈춘 주의색 고리로 바꿉니다. 사이드바의 그 채팅에 "승인 대기"가 표시됩니다.
  - 승인 카드가 나타나도 **포커스를 빼앗지 않습니다.** 사용자가 글을 쓰는 중일 수 있습니다.
  - 정해진 시간 뒤에 저절로 허용하거나 거부하지 않습니다.
- **생각 과정**: 모델의 추론을 보여 줄 때는 답변 위에 접힌 한 줄("생각 과정 · 4초")로 두고, 누르면 펼칩니다. 펼친 내용은 왼쪽 2px `--line` 막대, 12px `--text2`. 기본은 접힘입니다.
- **작성 중인 답변(스트리밍)**: 글자가 들어오는 끝에 깜빡이는 2px `--accent` 막대를 둡니다. 글자가 들어오는 동안 화면이 저절로 따라 내려가되, 사용자가 위로 올려 읽고 있으면 따라 내려가지 않습니다.
- **실패한 도구 호출**: 그 행의 결과 요약을 `--danger`로 쓰고("실패 · 종료 코드 1"), 펼치면 오류 출력이 보입니다. 색만이 아니라 "실패"라는 낱말이 함께 있습니다.
- **하위 에이전트**: 도구 호출 카드의 한 행으로 보여 주고, 펼치면 그 안의 도구 호출이 들여쓰기(16px)로 나옵니다. 새 종류의 카드를 만들지 않습니다.
- **대화 안의 알림**: 대화 흐름에서 일어난 일(컨텍스트를 요약함)은 가운데 정렬된 11px `--mute` 한 줄과 양옆의 `--line` 선으로 알립니다. 사용자가 정해야 이어지는 일(최대 턴 수에 도달)은 안내 띠(6.5) 모양에 버튼 하나("계속")를 둡니다.
- **그림·표 같은 출력**: 카드(5.5) 안에 넣고 최대 높이를 정해 넘치면 카드 안에서 스크롤합니다.
- **오류 카드**: 실행이 실패하면 대화 안에 카드로 남깁니다. 오류 표시(마름모) + 무슨 일이 일어났는지 한 문장 + 할 수 있는 일 + "다시 시도" 버튼. `role="alert"`. 토스트로만 알리고 사라지게 하지 않습니다. 제공업체 오류, 연결 끊김도 이 카드로 알립니다.
- **답변 아래 동작**: 복사, 같은 요청 다시 실행. `--mute` 색 아이콘 버튼이고 올리면 `--text`.
- **응답 작성 중**: 점 3개.
- **파일 트리**(사이드 패널의 파일 탭): 행 높이 28px, 깊이마다 들여쓰기 16px, 폴더는 펼침 화살표, 선택된 파일은 `--sel` 면 + 왼쪽 2px `--text` 막대 + 굵기 500. 역할은 `tree` + `treeitem`, 화살표 위아래로 옮기고 좌우로 접고 폅니다.
- 위 요소 가운데 생각 과정, 스트리밍, 실패한 도구 호출, 대화 안의 알림, 오류 카드, 첨부, 파일 트리는 **시안에는 없고 `ui/gallery.html`에 있습니다.** / 메뉴와 하위 에이전트는 규칙만 있습니다.

### 5.14 그 밖의 세부

- **스크롤바**: 가늘게 항상 보입니다(`scrollbar-width: thin`, 손잡이는 `--text` 30%). 올렸을 때만 보이게 숨기지 않습니다. Windows에서는 스크롤할 수 있다는 것을 스크롤바로 압니다.
- 글자 선택 색은 `--accent` 30%. 입력 커서 색은 `--accent`.
- 타이틀바, 사이드바, 버튼의 글자는 끌어서 선택되지 않게 합니다. 본문과 대화는 선택됩니다.
- 단축키 힌트: "새 채팅"과 "설정" 항목은 올렸을 때 오른쪽에 단축키가 보입니다(Ctrl+T처럼 +로 잇습니다).
- **빈 상태**: 카드 안에 제목(15px 600), 설명 한 줄, 그리고 **다음에 할 수 있는 동작이 있으면 그 버튼**(기본 버튼). 장식 그림은 넣지 않습니다. 검색 결과가 없을 때는 "일치하는 ○○이 없습니다"로 문구를 구분합니다.
- **선택 막대**(`.bulkbar`): 여러 개를 골랐을 때 화면 아래 가운데에 뜨는 캡슐. "N개 선택됨" + 동작 버튼들 + "선택 해제". 목록을 밀어내지 않습니다. `role="toolbar"`.

## 6. 새 컴포넌트를 만드는 규칙

### 6.1 만들기 전에 (이 순서로 확인)

1. **5장에 같은 역할이 있는가.** 있으면 그것을 씁니다. 모습이 조금 달라야 해도 새로 만들지 않습니다.
2. **기존 컴포넌트에 종류를 하나 더하면 되는가.** 되면 종류(variant)를 추가합니다.
3. **기존 컴포넌트를 조합하면 되는가.** 되면 조합합니다(예: 카드 + 행 + 토글).
4. **Radix에 그 동작을 하는 부품이 있는가.** 있으면 그 위에 스타일을 입힙니다. 키보드 조작과 포커스 처리를 직접 만들지 않습니다.
5. 위 넷이 모두 아닐 때만 새로 만듭니다.

### 6.2 새 컴포넌트가 지켜야 하는 것

- [ ] 색은 3.1의 토큰만 씁니다. 색상 값을 직접 쓰지 않습니다.
- [ ] 글자 크기는 3.3, 높이는 3.4, 모서리는 3.5, 간격은 3.6, 층은 3.7에서 고릅니다.
- [ ] 누를 수 있으면 4장의 상태(기본, 올림, 누름, 포커스, 쓸 수 없음)를 모두 가집니다.
- [ ] 값을 넣거나 고르는 컨트롤이면 바탕과 3:1 이상으로 구분되는 경계가 있습니다.
- [ ] 라이트와 다크에서 10.1의 대비를 확인합니다. Aura에서도 열어 봅니다.
- [ ] 누를 수 있는 것은 `button`이거나 Radix 부품입니다. `div`에 클릭을 달지 않습니다.
- [ ] 아이콘만 있으면 `aria-label`과 툴팁이 있습니다.
- [ ] 키보드만으로 쓸 수 있습니다(10.3).
- [ ] 색만으로 상태를 구분하지 않습니다. 모양이나 글자가 함께 바뀝니다.
- [ ] 움직임이 있으면 3.8의 값을 쓰고, "움직임 줄이기"에서 꺼집니다.
- [ ] 고대비 모드에서 켜짐·선택됨·포커스가 구분됩니다(10.4).
- [ ] 문구는 9장을 따릅니다.
- [ ] `node scripts/design-check.mjs`가 통과합니다.
- [ ] 6.4 양식으로 이 문서 5장에 등록합니다.

### 6.3 값 고르는 법

| 정할 것 | 고르는 법 |
|---|---|
| 높이 | 한 줄 컨트롤은 28px. 목록 속의 작은 것은 24px. 목록 행은 30px(사이드바)이나 44px(설정) |
| 모서리 | 누르는 컨트롤은 999px. 글자를 입력하는 칸은 8px. 담는 상자와 메뉴는 12px. 창은 20px |
| 면 | 누르는 컨트롤은 `--fill`. 값 컨트롤은 `--fill`과 `--ctl-line`. 담는 상자는 `--panel`과 `--line` 테두리. 상자 안의 선택지는 `--group` |
| 글자 | 이름은 13px, 설명은 11px `--mute`, 제목은 15px 600 |
| 강조 | 켜짐·포커스·진행·링크에만 `--accent`. 그 밖에는 무채색 |
| 그림자 | 다른 것 위에 뜨면 `--pop`. 화면을 가리는 창이면 `--shadow`. 그 밖에는 없음 |
| 층 | 3.7의 토큰. 숫자를 직접 쓰지 않습니다 |
| 아이콘 | 16px, 선 굵기 1.6, `currentColor`. 저장소의 기존 아이콘 묶음을 씁니다 |

### 6.4 등록 양식

새 컴포넌트를 만들면 5장 끝에 아래 양식으로 추가하고, 14장 변경 기록에 한 줄 적습니다.

```md
### 5.x 이름 (컴포넌트 파일 경로)

- 쓰는 때: (한 문장. 기존 컴포넌트로 안 되는 이유 포함)
- 구조: (부품과 순서)
- 치수: 높이, 모서리, 안쪽 여백 (3장의 토큰으로)
- 색: 기본 / 올림 / 누름 / 선택 / 쓸 수 없음 (토큰 이름으로)
- 역할과 이름: (role, aria 속성)
- 키보드: (조작 방법, 포커스가 어디로 가는지)
- Radix: (쓴 부품, 없으면 "없음")
- 쓰지 않는 때: (헷갈리기 쉬운 경우)
```

### 6.5 예시: 규칙대로 만든 두 가지

아래 둘은 지금 앱에 없는 컴포넌트입니다. 규칙을 적용하면 어떻게 정해지는지 보여 주는 예입니다.

**진행 막대**
- 쓰는 때: 얼마나 끝났는지 숫자로 알 수 있는 작업(내려받기, 여러 파일 처리). 끝을 모르면 회전 고리를 씁니다.
- 구조: 바탕 막대 + 채워진 막대, 오른쪽에 보조 글자로 "3/10".
- 치수: 높이 6px, 모서리 999px.
- 색: 바탕 `--fill2`, 채움 `--accent`(진행은 강조색을 쓰는 네 곳 중 하나). 끝나도 색을 바꾸지 않고, 숫자가 "10/10"이 되고 옆에 완료 표시(5.11)를 붙입니다.
- 역할과 이름: `role="progressbar"`, `aria-valuenow`, `aria-valuemax`, 무엇의 진행인지 `aria-label`.
- 키보드: 없음(누르는 것이 아님).
- Radix: Progress.

**안내 띠**
- 쓰는 때: 화면 전체에 해당하는 알림(연결 끊김, 새 버전). 한 동작의 결과는 토스트를 씁니다.
- 구조: 본문 맨 위, 상태 표시 + 문장 한 줄 + 오른쪽에 동작 버튼 하나(작은 버튼) + 닫기 아이콘 버튼.
- 치수: 최소 높이 44px, 안쪽 8px 14px, 모서리 12px.
- 색: `--panel` 면, `--line` 테두리. 종류는 상태 표시의 색과 모양으로 구분합니다(5.11). 면 전체를 색칠하지 않습니다.
- 역할과 이름: `role="status"`(오류는 `role="alert"`). 닫기 버튼에 `aria-label`과 툴팁.
- 키보드: Tab으로 동작 버튼과 닫기 버튼에 닿습니다.
- Radix: 없음.

### 6.6 규칙에 없는 값이나 경우를 만났을 때

1. 먼저 가장 가까운 기존 값으로 되는지 봅니다. 대부분 됩니다.
2. 정말 새 값이 필요하면 **토큰을 먼저 추가**합니다: `metis-tokens.css`와 이 문서 3장을 고치고, 14장에 이유를 적습니다. 그 다음에 씁니다.
3. 컴포넌트 안에 값을 직접 쓰고 넘어가지 않습니다.
4. **멈추고 사람에게 묻는 경우**: 원칙(2장)을 바꿔야 할 때, 기능이나 저장 방식이 바뀔 때, 기존 화면에 있는 요소를 이 문서로 설명할 수 없을 때, 이 문서의 두 규칙이 서로 맞지 않을 때.

## 7. 새 화면을 만드는 규칙

새 화면은 아래 틀 중 하나로 만듭니다. 틀에 없는 배치를 새로 짜지 않습니다.
본문 안쪽 최대 폭은 **모든 페이지에서 920px**로 같습니다(대화와 입력창만 760px). 화면을 옮겨 다닐 때 제목 위치가 흔들리지 않게 하려는 것입니다.

### 7.1 목록 화면 (레시피, 스킬, 스케줄러와 같은 종류)

```
[큰 제목]                          [검색 칸] [기본 버튼] [주요 버튼]
[설명 한 줄, --mute]

[카드: 행 묶음]
  이름 / 설명                      [작은 버튼] [토글] [⋯]
```

- 페이지 제목은 `h1`입니다.
- 본문의 주요 버튼은 하나(만들기). 나머지는 기본 버튼.
- 행의 동작은 5.5의 한도를 따르고, 넘으면 ⋯ 메뉴에 모읍니다.
- 항목이 없으면 같은 자리에 빈 상태 카드(5.14).
- 검색은 오른쪽 위 검색 칸. "Ctrl+F로 검색" 같은 안내 문장을 쓰지 않습니다. Ctrl+F를 누르면 그 검색 칸으로 포커스가 갑니다.

### 7.2 격자 화면 (채팅 기록과 같은 종류)

- 날짜나 종류별로 묶고, 묶음 제목은 11px 600 `--mute`.
- 카드 최소 폭 260px. 카드에는 제목, 보조 글자 한두 줄, ⋯ 메뉴.
- 여러 개를 고르는 화면이면 카드에 체크 상자를 두고, 하나라도 고르면 **선택 막대**(5.14)가 화면 아래에 뜹니다. 목록 위에 줄을 끼워 넣어 목록을 밀지 않습니다.
- **선택은 지금 보이는 항목에만 적용됩니다.** 검색으로 걸러서 안 보이는 항목은 선택 수에 넣지 않고, 일괄 삭제에도 넣지 않습니다.

### 7.3 설정 화면

```
[큰 제목]
[그룹 제목, 11px 600]
[카드: 행 묶음]
  이름 / 설명                      [컨트롤]
```

- "분류 → 그룹 제목 → 카드 → 행" 구조.
- 행의 컨트롤은 5.5의 한도를 따릅니다. 종류는 5.3의 표로 고릅니다.
- 숫자 입력 뒤에는 단위를 적습니다.
- 컨트롤과 그 행의 설명 글을 `aria-describedby`로 잇습니다.
- 주의할 내용은 색 상자 대신 상태 표시와 한 줄 안내로.
- 새 설정 분류를 만들면 사이드바 설정 목록에 아이콘과 함께 넣습니다.
- **저장 시점은 앱의 기존 동작을 유지합니다.** 지금 바로 저장되는 항목은 바로 저장, 저장 버튼이 있는 항목은 버튼을 그대로 둡니다. 이 문서는 저장 시점을 바꾸지 않습니다.

### 7.4 창(모달)과 입력 검증

**입력을 받는 창**: 제목, 입력들(라벨 위, 입력 아래, 사이 14px), 버튼 줄(5.9).

**검증**
- 확인하는 때: 실행 버튼을 눌렀을 때. 치는 도중에 오류를 띄우지 않습니다.
- 잘못된 칸: 4장의 "잘못된 값" 모습 + 칸 바로 아래에 11px `--danger` 문장(`role="alert"`) + `aria-invalid="true"`. 문장은 무엇을 넣어야 하는지 말합니다("프로젝트 이름을 입력하세요").
- 포커스는 잘못된 첫 칸으로 갑니다. 창은 닫지 않습니다.
- 그 칸을 고치기 시작하면 오류 표시가 사라집니다.
- **입력 오류를 토스트로 알리지 않습니다.** 토스트는 사라지고, 어느 칸인지 알려 주지 못합니다.
- 설정 화면의 숫자 칸처럼 창 밖에 있는 입력은 값이 바뀔 때 확인합니다. 잘못되면 **이전 값을 유지하고** 칸 아래에 이유를 적습니다.
- 값의 범위(최소, 최대)가 있으면 설명 글에 적습니다.
- 시각은 24시간 형식(09:00)으로 받고, 형식이 틀리면 오류로 알립니다.
- 단축키를 바꿀 때 이미 쓰이는 조합이면 저장하지 않고 어디에서 쓰는지 알립니다. 단축키 입력 상자는 Esc를 조합으로 잡지 않습니다(Esc는 창을 닫습니다).

**작성 중인 내용 보호**
- 내용을 고친 창을 Esc나 닫기 버튼으로 닫으려 하면 같은 창 안에서 "작성 중인 내용을 버릴까요?"를 묻습니다. 버튼은 "버리고 닫기"(위험), "계속 작성"(기본).
- 아무것도 고치지 않았으면 바로 닫습니다.
- "취소" 버튼은 묻지 않고 닫습니다. 사용자가 이미 버리겠다고 한 것입니다.

**확인 창(되돌릴 수 없는 동작)**
- 삭제, 초기화처럼 되돌릴 수 없는 동작은 **예외 없이** 확인 창을 거칩니다. 다른 창 안에 있는 삭제 버튼도 마찬가지입니다.
- 제목은 무엇을 하는지 묻는 문장입니다: "채팅을 삭제할까요?", "제공업체를 삭제할까요?". "확인"이라고 쓰지 않습니다.
- 본문에 무엇이 사라지는지와 "이 동작은 되돌릴 수 없습니다."를 적습니다. 여러 개면 개수를 적습니다.
- 버튼: 위험 버튼(하는 일의 동사, "삭제") 왼쪽, "취소" 오른쪽. 열렸을 때 포커스는 **취소**에 둡니다. Enter를 잘못 눌러 지워지지 않게 하려는 것입니다.
- `alert`, `confirm`, `prompt`를 쓰지 않습니다. Radix AlertDialog를 씁니다.

"현재" 칸은 화면 캡처를 보고 적은 것입니다. 실제 코드와 다르면 코드가 맞고, 차이를 보고에 적습니다.

## 9. 문구

- 버튼은 **하는 일을 동사로** 씁니다: "저장", "삭제", "가져오기". "확인", "예"를 쓰지 않습니다.
- **말줄임표(…)**: 누른 뒤에 **입력을 더 받아야 일이 끝나는** 버튼과 메뉴 항목에 붙입니다("가져오기…", "이름 바꾸기…", "레시피 생성…"). 바로 실행되는 것("실행", "복제")과, 확인만 한 번 묻는 것("삭제")에는 붙이지 않습니다. 점 세 개(...)가 아니라 말줄임표 문자(…)를 씁니다.
- 버튼은 2~6자, 창 제목은 15자 안쪽. "이 채팅에서 항상 허용"처럼 뜻을 줄일 수 없으면 넘겨도 됩니다.
- 설명은 한 문장, 합니다체("저장합니다").
- **같은 것은 같은 낱말로** 부릅니다. 대화는 "채팅"입니다("세션"이라고 쓰지 않습니다). 운영체제 용어는 Windows 것을 씁니다("시스템 트레이", "설정").
- 빈 상태: 제목은 지금 상태("저장된 레시피가 없습니다"), 설명은 다음에 할 일.
- 오류: 무슨 일이 일어났는지와 할 수 있는 일을 한 문장씩. 사용자를 탓하지 않습니다.
- 확인 창: 제목은 묻는 문장, 본문에 "이 동작은 되돌릴 수 없습니다."
- 단축키는 +로 잇습니다(Ctrl+T, Ctrl+Shift+N).
- 숫자와 단위는 띄어 씁니다("10 분"이 아니라 입력 칸 뒤의 단위 글자는 따로 둡니다). 개수는 "3개", "메시지 190개".
- **문구가 있는 곳**: 저장소에 번역 구조(i18n)가 있으면 바꾸는 문구를 그 파일에서 고칩니다. 없으면 **만들지 않습니다.** 코드에 있던 자리에서 고칩니다. 번역 구조를 새로 넣는 일은 이 문서의 범위가 아닙니다.
- 영어 같은 다른 언어 문구가 이미 있으면 한국어와 함께 고칩니다. 문장이 길어져도 버튼과 행이 깨지지 않게 폭을 고정하지 않습니다.

### 10.2 역할과 이름

- 누를 수 있는 것은 모두 `button`이거나 Radix 부품. `div`에 클릭을 달지 않습니다.
- 페이지 제목은 `h1`, 창 제목은 `h2`.
- 역할: 토글 `switch`, 구간 선택·선택 카드 `radiogroup` + `radio`, 체크 상자 `checkbox`, 탭 `tablist` + `tab`, 창 `dialog` + `aria-modal`, 토스트 `status`, 대화 영역 `log`, 선택 막대 `toolbar`.
- 접이식 구역, 도구 호출 행, 메뉴를 여는 버튼에는 `aria-expanded`. 메뉴를 여는 버튼에는 `aria-haspopup`.
- 눌러서 켜지는 버튼(패널 버튼, 비밀 값 보기)에는 `aria-pressed`.
- 현재 화면의 내비게이션 항목에는 `aria-current="page"`.
- 아이콘만 있는 버튼에는 `aria-label`. 상태 표시에는 상태 이름.
- 입력에는 라벨, 설명은 `aria-describedby`, 오류는 `aria-invalid`와 `role="alert"`.
- 색만으로 구분하지 않습니다.

### 10.3 키보드

Radix 부품을 쓰면 아래 대부분이 기본으로 됩니다. 기본 동작을 끄지 않습니다.

| 키 | 동작 |
|---|---|
| Tab / Shift+Tab | 다음 / 이전 컨트롤. 창이 열려 있으면 창 안에서만 돕니다. 창 컨트롤(최소화 등)은 Tab 순서에 넣지 않습니다 |
| Enter, Space | 포커스가 있는 버튼 실행. 한 줄 입력에서 Enter는 그 창의 주요 동작 실행 |

| 화살표 위아래 | 메뉴 항목, 라디오 묶음(세로) 옮기기 |
| 화살표 좌우 | 탭, 구간 선택 옮기기. 파일 트리 접고 펴기 |

### 10.4 운영체제 설정

- **움직임 줄이기**(`prefers-reduced-motion: reduce`): 3.8.
- **고대비**(`forced-colors: active`, Windows의 대비 테마): 시스템 색이 강제로 적용되어 면 색으로만 알리던 것이 사라집니다. 아래를 지킵니다.
  - 면 색으로 구분하던 컨트롤(버튼, 입력, 카드, 메뉴, 창)에 `outline: 1px solid transparent`를 둡니다. 고대비에서는 이 외곽선이 시스템 색으로 보입니다.
  - 켜짐·선택됨은 시스템 색으로 다시 정합니다: 켜진 토글·체크 상자·라디오와 선택된 내비게이션 항목·구간 선택 칸은 `Highlight` 면에 `HighlightText`. 이 요소들에는 `forced-color-adjust: none`을 주고 시스템 색 낱말로 값을 적습니다.
  - 포커스 링은 `Highlight`. 포커스를 `outline`으로 그렸다면 따로 할 일이 없습니다(4장).
  - 켜진 아이콘 버튼, 선택된 탭, 선택된 파일도 `Highlight` 면에 `HighlightText`.
  - 상태 표시는 모양으로 구분되므로 색은 `ButtonText` 하나로 둡니다.
- **색 구성표**(`prefers-color-scheme`): 테마 설정이 "시스템"일 때만 따릅니다.
- **배율**: Windows의 100%, 125%, 150%에서 선이 흐려지거나 글자가 잘리지 않는지 봅니다. 소수점 px을 쓰지 않는 이유입니다(3.6).

### 10.5 Windows 관례

- 창 컨트롤은 오른쪽 위에 최소화, 최대화, 닫기 순서입니다. 닫기는 올리면 빨간 면(`--close-hover`)입니다.
- **가능하면 Electron의 `titleBarOverlay`로 운영체제의 창 컨트롤을 씁니다.** 그래야 최대화 버튼에 올렸을 때 Windows 11의 창 맞춤 배치(Snap Layouts)가 뜹니다. 지금 직접 그린 컨트롤을 쓰고 있다면 그대로 두고 13.2에 적힌 대로 확인을 받습니다.
- 타이틀바는 끌어서 창을 옮길 수 있고(`-webkit-app-region: drag`), 그 안의 버튼은 `no-drag`입니다. 더블 클릭하면 최대화됩니다.
- 대화 상자의 버튼 순서는 주요 동작 왼쪽, 취소 오른쪽입니다(5.9).
- 폴더와 파일은 운영체제의 선택 창으로 고릅니다(5.2).
- 스크롤바는 항상 보입니다(5.14).
- 목록 항목은 오른쪽 클릭 메뉴를 가집니다(5.4).

## 11. 구현 (React, TypeScript, Tailwind, Radix, Electron)

### 11.1 원칙

- **기존 컴포넌트를 고쳐 씁니다.** 같은 역할의 컴포넌트를 새로 만들어 병행하지 않습니다.
- **공용 컴포넌트를 한 곳에 둡니다.** 버튼, 입력, 토글, 메뉴 같은 것은 저장소의 공용 UI 폴더에 하나씩만 있고, 화면은 그것을 가져다 씁니다. 화면 파일 안에서 버튼 모양을 Tailwind 클래스로 다시 짜지 않습니다.
- 종류(기본, 주요, 위험)는 컴포넌트의 prop으로 고릅니다. 저장소가 이미 쓰는 방식(예: `cva`, `clsx`, `tailwind-merge`)을 따르고, 없는 도구를 새로 넣지 않습니다.
- 의존성을 새로 넣지 않습니다. 필요한 Radix 부품이 저장소에 없으면 멈추고 묻습니다.

### 11.2 토큰을 Tailwind에 연결

1. 저장소의 테마 구현을 먼저 읽습니다. 이미 CSS 변수와 Tailwind 색 이름이 있으면 **그 변수의 값을 3.1에 맞춰 바꾸고**, 없는 토큰만 추가합니다. Aura의 색 값은 건드리지 않습니다(3.1).
2. 대응 관계를 `docs/design/TOKEN_MAP.md`에 표로 적습니다(이 문서의 토큰 ↔ 저장소 변수 ↔ Tailwind 클래스). 이후 작업은 이 표를 따릅니다.
3. Tailwind 버전을 `package.json`에서 확인하고 그 버전의 방식을 씁니다.

기존 체계가 없을 때 쓰는 Tailwind 이름입니다. CSS 변수 이름은 짧지만 Tailwind 이름은 **뜻이 드러나게**, 그리고 **Tailwind의 기본 이름과 겹치지 않게** 붙였습니다. 겹치면(`rounded-lg`, `font-sans` 등) 아직 고치지 않은 화면의 모습이 함께 바뀝니다.

| 토큰 | Tailwind 이름 | 예 |
|---|---|---|
| `--bg` / `--side` / `--panel` | `surface` / `surface-side` / `surface-raised` | `bg-surface` |
| `--text` / `--text2` / `--mute` | `ink` / `ink-2` / `ink-mute` | `text-ink-mute` |
| `--line` / `--ctl-line` | `line` / `line-control` | `border-line` |
| `--fill` / `--fill2` / `--fill3` | `control` / `control-hover` / `control-press` | `bg-control hover:bg-control-hover active:bg-control-press` |
| `--group` | `well` | `bg-well` |
| `--sel` / `--hover` | `selected` / `row-hover` | `bg-selected` |
| `--accent` / `--atext` / `--on-accent` | `accent` / `accent-ink` / `on-accent` | `bg-accent`, `text-accent-ink` |
| `--ring` | `focus` | `outline-focus` |
| `--btn` / `--btn-ink` | `primary` / `primary-ink` | `bg-primary text-primary-ink` |
| `--ok` / `--warn` / `--danger` / `--dsoft` | `ok` / `warn` / `danger` / `danger-soft` | `text-danger bg-danger-soft` |
| `--bubble` / `--code` / `--segsel` | `bubble` / `code` / `seg-selected` | `bg-code` |
| `--tip` / `--tip-ink` / `--scrim` | `tip` / `tip-ink` / `scrim` | `bg-tip text-tip-ink` |
| `--add-bg` `--add-tx` `--del-bg` `--del-tx` | `diff-add` `diff-add-ink` `diff-del` `diff-del-ink` | `bg-diff-add text-diff-add-ink` |
| 글자 크기 8단계 | `caption` `small` `body` `heading` `subtitle` `title` `display` `clock` | `text-body` |
| 모서리 5 / 8 / 12 / 16 / 20 / 999px | `tick` `field` `card` `bubble` `dialog` `pill` | `rounded-card` |
| 글꼴 | `app` `code` `brand` | `font-code` |
| 높이 | `control` `control-sm` `icon-btn` `nav` `row` `titlebar` | `h-control` |
| 그림자 | `pop` `modal` | `shadow-pop` |

**Tailwind 4** (CSS에서 설정). Tailwind 공식 문서의 테마 변수 이름 규칙(`--color-*`, `--text-*`, `--radius-*`, `--spacing-*`, `--shadow-*`, `--font-*`, `--ease-*`)과 `@theme inline`을 따랐습니다. 층(z-index)과 지속 시간에는 테마 이름 규칙이 없어서 `z-[var(--z-menu)]`, `duration-[var(--dur-state)]`처럼 변수를 직접 가리킵니다.

```css
@import "tailwindcss";
@import "./metis-tokens.css";

@theme inline {
  --color-surface: var(--bg);
  --color-surface-side: var(--side);
  --color-surface-raised: var(--panel);
```

### 11.3 Radix 상태와 4장의 대응

Radix 부품은 상태를 속성으로 내보냅니다. 클래스를 조건으로 바꾸지 말고 속성으로 스타일을 잡습니다.

| 4장의 상태 | Radix 속성 | Tailwind 예 |
|---|---|---|
| 켜짐(토글, 체크 상자, 라디오) | `data-state="checked"` | `data-[state=checked]:bg-accent` |
| 선택됨(구간 선택, 탭) | `data-state="on"` / `"active"` | `data-[state=on]:bg-seg-selected` |
| 열림(메뉴가 붙은 버튼, 접이식) | `data-state="open"` | `data-[state=open]:bg-control-hover` |
| 눌려 켜진 버튼(패널 버튼) | `data-state="on"` 또는 `aria-pressed="true"` | `aria-pressed:bg-control-press aria-pressed:ring-1 aria-pressed:ring-line-control aria-pressed:ring-inset` |
| 메뉴 항목 올림·키보드 이동 | `data-highlighted` | `data-[highlighted]:bg-control-hover` |
| 쓸 수 없음 | `data-disabled` | `data-[disabled]:opacity-[0.42]` |
| 키보드 포커스 | `:focus-visible` | `focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-focus` |

- 메뉴 항목은 `:hover`가 아니라 `data-highlighted`로 잡습니다. 그래야 키보드로 옮길 때도 같은 표시가 납니다.
- 툴팁은 `Tooltip.Provider`에 `delayDuration={900}`.
- 메뉴, 팝오버, 창, 툴팁은 각 부품의 `Portal`로 감쌉니다.
- 저장소의 Radix 불러오는 방식(`radix-ui` 한 묶음 또는 `@radix-ui/react-*`)을 그대로 따릅니다.
- 위 Tailwind 예는 11.2의 이름을 썼을 때입니다. 저장소 이름이 다르면 `TOKEN_MAP.md`의 이름으로 바꿉니다.

### 11.4 Electron에서 확인할 것

- **글꼴**: 3.2의 글꼴과 굵기를 앱에 함께 넣습니다(`@font-face`, 로컬 파일). 인터넷에서 불러오지 않습니다. 글꼴 파일의 사용 조건(Inter, Noto Sans KR, Sora, JetBrains Mono는 모두 SIL Open Font License)을 저장소의 고지 문서에 적습니다.
- **창 끌기와 창 컨트롤**: 10.5.
- **최소 창 크기**: 8.1.
- **입력창 자동 높이**: 시안은 `field-sizing: content`를 씁니다. 앱의 Electron(Chromium) 버전이 지원하지 않으면 기존의 높이 조절 코드를 씁니다.
- 시스템 테마 변화(`prefers-color-scheme`), 고대비(`forced-colors`), 움직임 줄이기에 반응하는지 확인합니다.
- 외부 링크는 앱 창이 아니라 기본 브라우저에서 엽니다. 기존 구현을 유지합니다.

### 11.5 Portal을 쓰지 않는 메뉴가 남아 있을 때

메뉴, 팝오버, 창, 툴팁을 Portal로 `body`에 붙이면 3.7의 층 순서만으로 충분합니다.
저장소에 Portal 없이 그 자리에 그리는 메뉴가 남아 있다면, 그 메뉴를 품은 요소에 `transform`, `filter`, 1 미만의 `opacity`를 주면 메뉴가 다른 것 아래로 내려갑니다. 그런 메뉴는 Portal을 쓰도록 고칩니다. 조상 요소의 스타일을 피해 가는 방식으로 풀지 않습니다.

### 11.6 참조 구현 `ui/`

| 파일 | 내용 |
|---|---|
| `ui/metis-tokens.css` | 토큰 값(라이트, 다크) |
| `ui/metis-components.css` | 4~5장의 컴포넌트를 `mt-` 클래스로 옮긴 CSS. 값은 모두 토큰. 고대비와 움직임 줄이기 포함 |
| `ui/gallery.html` | 위 CSS로 그린 견본. 브라우저로 열어 눌러 봅니다. 마크업을 복사해 쓸 수 있습니다 |
| `ui/README.md` | 리액트와 Radix에 붙이는 예 |

쓰는 방법은 둘 중 하나입니다. 0단계에서 저장소의 방식에 맞춰 고르고 `PLAN.md`에 적습니다.

- **A. CSS를 그대로 쓴다.** 두 파일을 불러오고, 기존 컴포넌트(Radix 부품 포함)에 `mt-` 클래스를 붙입니다. 상태는 `aria-*`와 Radix의 `data-state`를 CSS가 직접 읽으므로 조건부 클래스가 필요 없습니다. 가장 빠르고, 견본과 같은 모습이 바로 나옵니다.
- **B. Tailwind 클래스로 옮긴다.** 11.2의 이름으로 컴포넌트마다 클래스를 다시 씁니다. `ui/metis-components.css`의 그 컴포넌트 규칙을 값의 기준으로 삼습니다. 저장소가 Tailwind만 쓰기로 정해져 있을 때 고릅니다.

한 컴포넌트 안에서 A와 B를 섞지 않습니다. 저장소 전체로는 섞여 있어도 됩니다(공용 컴포넌트는 A, 화면 배치는 Tailwind).
